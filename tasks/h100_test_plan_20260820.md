# H100 test plan: prefill-launch-first (B) and coalesce removal (C)

Written 2026-08-20. One H100 session covers everything below. Protocol
mirrors tasks/prefill_launch_first_impl_log_20260817.md section 9 unless
stated: same corpus and benchmark client as the earlier gates, fresh server
per cell, one discarded warmup pass then one measured repeat per cell,
reverse-order control only on cells that decide a gate. Per cell record
req/s, p50/p95/p99 request latency, TTFT when the client reports it, WER on
the corpus.

## Arms

- A: upstream/main as checked out (knobs at shipped defaults).
- B: branch prefill-launch-first at origin (three commits on 24e9a3552).
- C: branch coalesce-removal (local; two commits on 99388dca4).
- B+C preview arm for the deciding matrix: cherry-pick the two C commits
  onto B (both are on nearby bases; resolve trivially) or zero the knobs on
  B by CLI: --prefill-coalesce-requests 0 on the launched model.

Local validation already done on this Mac (2026-08-19/20): unit failure sets
of B and of C are byte-identical to pristine upstream/main (28 pre-existing
in the B comparison set; 44 failed plus 10 collection errors in the wider C
comparison set, minus only the deleted CLI coalesce test). Not repeated on
the H100 unless a diff appears elsewhere.

## Phase 1: diagnosis (no gates, decides B3 and B4)

E-B3 Name the in-forward sync line. On arm B:
  python tasks/make_sync_probe.py sglang_omni/scheduling/omni_scheduler.py
  Run Qwen3-ASR c32, one warmup plus one measured pass. Collect every
  [sync-probe] and [sync-probe-cum] line. Revert with git. Repeat once on
  arm A so the sites match up. Deliverable: the named Python line(s) with
  counts; decides what B3 (fixing the launch stall) even is.

E-B4a The missing ArkASR probe cell. On arm A and arm B:
  apply tasks/probe_host_launch_first.py, run ArkASR c16, one pass each.
  Deliverable: per-key A/B diff (launch:extend, schedule:extend,
  resolve:extend, sync_run:extend, drain), extend launches per pass.
  Confirms or kills the host-saturation mechanism from
  tasks/arkasr_read_20260819.md (d)1.

E-B4b Batch shapes and forced drains. On arm A and arm B:
  python tasks/make_loop_counters.py sglang_omni/scheduling/omni_scheduler.py
  Run ArkASR c16, one pass each. Deliverable: the [loop-counters] batch
  histogram per forward mode and the drained_pending counts (an extend in
  drained_pending on B is a launched prefill that bought zero overlap).
  Note: drained_pending also counts drains from pause and weight updates;
  none occur in a benchmark pass.

## Phase 3: the deciding matrix for C (knob deletion)

Arms: A (main, knobs tuned as shipped) vs B+B4+C (launch-first with knobs
gone). Cells:
- Qwen3-ASR c1, c8, c32 (knobs shipped 16/40 ms; the model launch-first
  helps most).
- Higgs TTS c16, c32 (largest historical coalescing win, +31 percent at
  K=32/T=300; decides whether deletion without replacement is shippable).
- MOSS-TD c8, c16 (knobs shipped 4/12 ms with the build-aware branches).
- ArkASR c16 (must stay neutral; it never had knobs).
Reverse-order control on Higgs c32 and Qwen3-ASR c32.

Gate: B+B4+C at or above A within the single-repeat spread at every cell;
WER equal or single proper-name flips. If any cell fails, C stays parked
and the failing cell's probe pass (phase 1 tooling) is the next diagnosis.
