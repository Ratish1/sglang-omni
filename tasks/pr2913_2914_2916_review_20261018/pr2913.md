# PR 2913 review

## Summary and technical background

The talker consumes projected prompt rows on extend and the previous frame's summed codec embeddings plus the next projected text row on decode. A codec token embedding by itself is not the input contract of this model. The reference model's decode assembly likewise sums all codebooks before adding trailing text or the pad embedding.

This PR removes the old feedback buffer/mask and two unsupported fallbacks. It is invariant enforcement and dead-state removal, not a throughput optimization. The model's staging table remains `decode_feedback_embedding`; the old plain tensor and false mask were no longer its decode transport.

| Mechanical part | Changed files | Contract checked |
| --- | --- | --- |
| Decode staging | `model_runner.py` | Each real row must have queued feedback before any table write or forward; text and exhausted-text pad rows retain batched stack/add. |
| Model input selection | `sglang_model.py` | Decode indexes the staging table; extend takes supplied embeddings. No alternate bare-codec path remains. |
| Prompt device/dtype ownership | `request_builders.py`, `prompt_frontend.py`, prompt constants | The live codec parameter supplies row width, element size, device and dtype for both the full talker and standalone frontend. |
| Graph capacity | `cuda_graph_batch_validator.py` | Capacity is read from the actual decode table, including its outer/inner alias. |
| Regression protection | Three test files | Staging arithmetic, queue consumption, missing feedback, prefill input selection, capacity and prepared-payload handoff. |

## Code quality and correctness

No correctness or performance defect was found. One small documentation cleanup remains.

Optional `[P3-STYLE] [C3-COMMENTS]`: [the prompt constants' dtype description](https://github.com/sgl-project/sglang-omni/blob/4fa680cb1f273673635d7bd2042597af8551b757/sglang_omni/models/qwen3_tts/sglang_model.py#L462) and [the prompt mixin's required-field description](https://github.com/sgl-project/sglang-omni/blob/4fa680cb1f273673635d7bd2042597af8551b757/sglang_omni/models/qwen3_tts/sglang_model.py#L476) still name the removed feedback buffer. Update them to the codec parameter's device/dtype and remove the obsolete required buffer. This is directly caused by the state removal; it needs no new unit test and is not a merge blocker.

The removed state has no remaining Qwen3-TTS production readers/writers. Qwen3-Omni still owns separate feedback buffers; those are not removed. Qwen3-TTS calls the shared runner's static queue/history helpers, not its buffer-writing instance method.

The failure does not require a recoverable partial write: the missing-row exception happens before the batched staging-table write. Earlier queue rows may have been consumed, but `OmniScheduler.run_batch` fails and aborts every request in that batch, marks their KV uncached, and continues serving. These requests are not retried with the consumed queues. Requiring transaction rollback here would add machinery without a real consumer.

The empty-batch return and input-ID/capacity checks remain. Padding rows are graph padding, not scheduler requests, so the new requirement applies to live rows only. Reading stale padded table rows does not introduce a live-request embedding fallback.

## Goal completeness

All supported input producers were followed: Base ICL/x-vector, CustomVoice, VoiceDesign, standalone prepared payloads, ordinary prefill, chunk windows and generated-history re-prefill. The request builder initializes text/pad state and prompt rows; non-EOS completion appends the next feedback row; EOS terminates the request. Decode lookahead is explicitly disabled for this runner because that path lacks codec collection.

Chunk/retraction advancement is a separate concern addressed by merged #2911. This PR's branch predates that merge; its description explicitly identifies the #2911 repair used in its chunked model test. Missing that pre-existing chunk fix is not a new embedding-removal finding. GitHub reported this head mergeable into current main.

The PR's seeded full-corpus/audio-identity results are author-reported. Independent review validation covered the concrete bookkeeping paths; see `verification.md` for the exact distinction.

## Coherence and system fit

The codec parameter is the natural dtype/device owner for prompt construction. Removing a fake frontend buffer improves that ownership. The capacity probe now follows the same embedding table the graph reads. There is no new runtime abstraction, hardware threshold or fallback policy to maintain.

The implementation fits SGLang's explicit extend-embedding transport and fixed-address decode buffers. No runtime or vocoder redesign is needed for this change.
