# PR 2914 review

## Summary and technical background

Qwen3-TTS has no spatial position axes. The reference talker expands one sequence-position vector into three identical MRoPE rows. Selecting any temporal/height/width lane therefore selects the same angle at that lane's original frequency. Removing the MRoPE-only config keys is a valid model-level simplification, not a heuristic inferred from a benchmark.

SGLang's RoPE factory uses `mrope_section` to select `MRotaryEmbedding`. Removing it selects ordinary text RoPE. The shared Qwen attention then becomes eligible for fused RoPE plus KV-store, and live forward batches stop computing MRoPE positions. Full and breakable prefill graphs use the ordinary position slot, which the registry refreshes on replay.

## Code quality and correctness

### F1: P2 — preserve the CUDA native-backend path

The new normalization at [stages.py:165](https://github.com/sgl-project/sglang-omni/blob/9f1840ee4322921b3f10016634ce32a449b7b7e6/sglang_omni/models/qwen3_tts/stages.py#L165) enables a previously unreachable branch in the shared attention's [KV-store selector](https://github.com/sgl-project/sglang-omni/blob/9f1840ee4322921b3f10016634ce32a449b7b7e6/sglang_omni/models/qwen3_omni/components/thinker_model.py#L322).

The selector checks CUDA, KV-pool eligibility and the RoPE class. It does not check the selected fused-op backend. With the supported `SGLANG_FORCE_FUSED_OP_BACKEND=torch` diagnostic override, SGLang routes the text RoPE to `forward_native`, whose contract rejects `fused_set_kv_buffer_arg`. The call raises `AssertionError: fused_set_kv_buffer_arg is not supported for native implementation`.

This was reproduced with real CUDA RoPE, real Q/K normalization and a real BF16 MHA KV pool. The fixture supplies attention/batch wiring, not substitute math. The controls are:

| Path | Result |
| --- | --- |
| Previous MRoPE + forced Torch | Passes |
| New text RoPE + normal CUDA | Passes |
| New text RoPE + forced Torch | Fails at the native RoPE argument assertion |
| New text RoPE + forced Torch, fused store disabled | Passes |

This is a supported CUDA diagnostic path, not an invalid media request or unavailable accelerator. The predictor in the same TTS model already checks backend eligibility in `resolve_predictor_rope_store`. The ordinary talker needs the equivalent guarantee: provide a fused-store argument only when the selected RoPE implementation supports it, and leave the separate attention KV store active otherwise. Keep normal CUDA fusion enabled.

Add one accelerator regression case beside the existing attention/RoPE tests. Run the real attention operation under native and normal CUDA selection; assert valid rotated outputs and the corresponding KV-write behavior. This guards a real failure and would turn red if a future class-only fusion check reappeared. Do not add a speed-threshold test or mock out RoPE.

Severity: P2 compatibility/correctness issue; it does not affect the default CUDA path and is not a reason to reject the text-RoPE design. Skill category: `[P2-MAINTAIN]`, supported backend contract.

### F2: optional P4 — qualify the similarity statement

The description says the -0.32 and -0.24 speaker-similarity differences are inside a 0.25-point main/main difference. -0.32 is outside that number. Report the measured differences without that claim, or provide enough A/A evidence to support the statistical conclusion. One main/main difference is not a noise distribution. This is a wording/evidence correction, not proof that audio quality regresses. Skill category: `[P4-PROCESS]`.

No separate P3 style finding is warranted. The shared helper has actual ASR/TTS callers. A new utility-owned test file is defensible; moving it merely to avoid a small file would not improve the mechanism.

## Goal completeness

The equal-axis derivation was independently checked in FP32, including endpoint and large positions. The production CUDA fused operation was compared to that arithmetic with a BF16 output-rounding bound, for int32 and int64 position/cache indices. Three graph replays per index type changed both positions and nonconsecutive cache destinations; Q/K rotation, K/V values and untouched cache rows passed.

This is not bit-identical to the previous serving kernel. MRoPE's CUDA path narrows its trigonometric cache to the query dtype; ordinary CUDA RoPE keeps FP32 angles and computes before output rounding. The description correctly acknowledges that difference. Model-quality evidence must remain separate from the mathematical position equivalence.

ASR's changed tests passed on the H200 container. The pinned Transformers config alias was checked with real config objects; adding duplicate legacy-field handling is unnecessary for that supported pin.

Real 1.7B Base serving also passed with both full and breakable prefill graphs. Both launches completed warmup and four explicit buffered/streaming requests with different prompt lengths. Model-info counters confirmed the requested backend and graph replays without eager fallback. This establishes lifecycle/replay operation for the tested configuration, not corpus quality or a performance gain.

## Coherence and system fit

Normalize once before the runtime derives its model properties, then let SGLang own position buffers, RoPE dispatch and KV layout. This removes per-forward patching and uses SGLang's intended execution path. It is the right abstraction boundary. No new kernel, model-independent graph framework or hardware constant is needed.

The remaining eligibility bug is precisely at the interface between that model-level choice and the existing shared attention implementation. Fix that interface rather than undoing the config normalization.
