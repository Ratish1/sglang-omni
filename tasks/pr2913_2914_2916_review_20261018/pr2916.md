# PR 2916 review

## Summary and technical background

The fifteen residual codebooks have equal vocabulary and hidden widths. Their independent matrices can be represented as one `(codebooks, vocabulary, hidden)` parameter without changing any row. Offsetting a code by `codebook_index * vocabulary` selects the same row from the flattened parameter.

The optimization is on Base ICL prompt preparation: one residual embedding call replaces fifteen calls. The first codebook remains the talker's separate codec table. This is not equivalent to reducing the residual codebooks first and adding codebook zero later; that would change BF16 reduction order. The PR correctly retains the complete sixteen-codebook concatenation and the same final sum.

## Code quality and correctness

No actionable P0-P3 code finding remains from this review.

Every production consumer of Qwen3-TTS residual embeddings was searched. The generic fused-predictor utility consumes transformer layers and projections, not the old ModuleList of embeddings. There is no forgotten index/call consumer. The CUDA gather receives a contiguous 2-D view with the correct storage offset, so its stride and alias gates still apply.

`row_offsets` stays integer under `.to(dtype=...)` and follows the module's device. The loader copies into the existing destination dtype/device, just as the previous embedding loader did. The standalone frontend maps checkpoint names explicitly and checks the set of original names, so stacking cannot hide one missing table behind a single loaded-parameter name.

The table initialization follows the previous embedding modules' random initialization. Changing it to uninitialized storage might be a separate load-time cleanup, but no measurable startup problem was established here; it is not a merge requirement. Tests compare arithmetic for any valid row, so an unseeded generated index does not itself make those equality checks flaky.

Optional `[P4-PROCESS]` reporting cleanup: the description explicitly excludes two main-arm outliers from its WER table. Put full-corpus WER first, then filtered WER and the outlier counts. Those outputs are part of the measured corpus even when they are garbled or reach the frame cap. The exclusion is disclosed and favors main here, so it is not evidence of a concealed branch regression or a reason to block the code.

## Goal completeness

Base ICL is the changed prompt path. X-vector-only prompts, CustomVoice and VoiceDesign have no reference-code lookup, while their predictor decode uses the new views. The actual predictor chain, both CUDA graph replay and eager execution, remains covered. Projection derivation still omits the last residual codebook because no later predictor step consumes it.

The existing GPU suites passed 103 cases, with one Ascend-only skip. Five focused loader/prompt tests passed, including reverse checkpoint order and omission of a residual table. See `verification.md` for the additional checkpoint-width probe and the boundary between independently observed and author-reported results.

The independent real-checkpoint frontend probe subsequently passed: all 15 BF16 matrices matched their original checkpoint names, storage rebinding was followed, and three ICL cases were bit-identical to the actual pre-PR prompt builder at the 2048-wide checkpoint shape. No reduction-order tolerance was needed.

The weight-sharing attachment path was read through its actual `.data` rebind and pre-capture ordering. Qwen3-TTS is currently audit-only in the architecture allowlist, so this review does not claim a supported end-to-end IPC deployment test. New views do follow pre-capture rebinds; requesting unrelated IPC enablement in this PR would be out of scope.

## Coherence and system fit

The small model-owned module is shared by the full talker and its standalone prompt frontend. It belongs in Qwen3-TTS and does not require a generic scheduler utility. Shared checkpoint-name mapping prevents the two loaders from independently encoding the new layout.

SGLang uses model-specific loaders for stacked checkpoint tensors. Its multimodal-generation DAC codec has codebook-specific projections and potentially different widths, so it is not a drop-in abstraction for this equal-width talker embedding operation. Reusing that module would conflate different codec mechanics. No hardware, reference-duration or corpus threshold is introduced.
