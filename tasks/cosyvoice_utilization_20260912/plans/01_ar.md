# AR reporting and asynchronous scheduling

Open PR #2128 changes seed-tensor H2D construction, adjacent to A1 but distinct from sampled-token D2H. Open #1669 sets the upstream overlap flag alone and collides with A2; it does not close the Cosy history/commit/abort/drain contract. Check [report 17](../reports/17_open_prs.md) before touching these owners.

## A1: materialize reporting tokens once

Owner: `FunCosyVoice3ModelRunner._collect_tokens`, generic `ModelRunner._stage_token_ids/_resolve_host_token_ids/_finalize`, `SGLangOutputProcessor.process`, and `OmniScheduler._make_batch_result`. Evidence: reports 04, 05, 10, 11. Default execution is synchronous, so a reporting snapshot can be scoped to one completed batch without changing next-step scheduling.

Current flow samples on GPU, `.tolist()`s in Cosy codec collection, then generic output processing `.tolist()`s the same device tensor; upstream result processing normalizes it again. FutureMap publication independently preserves device tokens for the next forward. The existing optional host field already travels from `_finalize` to `ModelRunnerOutput.host_token_ids`, and the normal scheduler adapter prefers it for upstream reporting.

Design: at the first CPU-consumer boundary in Cosy, create one host snapshot through the existing staging helper, wait for its copy-completion event once before reading it, and retain the snapshot/event contract for `_finalize`. Use its CPU values for codec collection; generic output and upstream reporting then convert CPU data. Keep `result.next_token_ids` on GPU for FutureMap. Reuse the existing helpers instead of introducing another queue or asynchronous scheduler. `_resolve_host_token_ids` synchronizes and clears `_host_token_ids_event` while retaining `_host_token_ids`; call it before codec collection so `_finalize` reuses the same snapshot without another event wait. The snapshot must remain accessible until all normal-loop consumers finish, and not be overwritten by reuse. CPU execution follows the helper's CPU branch.

Preserve all 6761 IDs for finish processing and filter codec IDs only at the existing acoustic boundary. Preserve row order, EOS/minimum length, repetition penalty updates, first flush 28/subsequent 25, terminal chunk flush, retraction and aborted-row handling. Do not move device token publication onto a CPU round trip.

Remote proof: same fixed requests/seeds and shape sequence; exact sampled-ID history, emitted codec sequence, finish reason and usage; abort/length/stop and batch shrink/grow cases using existing H100 integration workloads. Trace the number and duration of token D2H copies per step and the host gap that disappears. A1 removes redundant materialization; it does **not** remove the first required host wait. If no service gain remains beyond noise, stop here or keep only a justified simplification. Roll back the Cosy staging call; no checkpoint or persistent state changes.

## A2: a real Cosy launch/resolve protocol

Not implementation-ready. Generic lookahead rejects Cosy's default history-dependent penalties and min-new-token logic. Its subclass collects codes in `post_decode`, which the generic resolve hook does not invoke. Upstream overlap also relies on dedicated streams, FutureMap publication, write-after-read barriers, copied batches and delayed result commits. Omni's existing start/stop finalization does not drain pending async work.

Before coding, specify the owner of speculative-next-step penalty state versus committed request history, token validity at stop/abort, exactly-once codec emission, and lagged row/KV release. Enumerate prefill↔decode, retraction, batch merge/filter, EOS/minimum-length, pause, weight update, exception and shutdown transitions. A state table must show which step owns each host buffer, GPU relay row and request resource until completion. Default sampling semantics must survive; disabling repetition penalty to make lookahead eligible is a workload change, not a solution.

If A1 leaves material CPU gaps and this contract is proved, separate the safe base lifecycle work from Cosy integration into two reviewable PRs. Reuse upstream primitives only at their demonstrated ownership boundary; do not copy the entire scheduler loop or switch `disable_overlap_schedule=False`.
