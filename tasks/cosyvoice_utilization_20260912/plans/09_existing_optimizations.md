# Assess existing optimizations before replacing them

The existing implementation is not presumed optimal merely because it uses a large backend or has an optimization flag. Conversely, the reported aggregate SM metric does not establish that a backend is wrong. Separate a correctness defect, a configuration mismatch, and a workload-dependent performance loss. The first two can invalidate a fast result; the third needs matched c1/c16 measurements.

The complete source reads behind this assessment are in reports [02](../reports/02_buffered_acoustics.md), [03](../reports/03_streaming_acoustics.md), [05](../reports/05_sglang_bridge.md), [11](../reports/11_upstream_execution.md), [12](../reports/12_cosyvoice_internals.md), [14](../reports/14_attention_backends.md), [15](../reports/15_upstream_config.md), and [16](../reports/16_fa3_backend.md). Live dispatch, installed binaries and measured gains remain unverified.

| Existing path | Established mechanics and qualification risk | Alternative and decision gate |
|---|---|---|
| AR continuous batching / decode graphs | Already reused from SGLang; default maximum 32, custom prefill eager. Host reporting still materializes sampled tokens. | First verify realized batch and graph replay. Use a graph-off diagnostic only when capture/padding is implicated; replacing the scheduler or enabling async requires the lifecycle proof in A2. |
| AR FA3 attention | Conditional ordinary H100/CUDA default, page size 1, installed `sgl_kernel.flash_attn`; backend name alone does not identify the binary or kernel. | Compare explicit FA3/FlashInfer/Triton only if supported by the same checkpoint, dtype, KV and graph contracts. Hold split prefill/decode overrides constant and preserve resolved logs. A faster isolated attention call is insufficient if setup, graph fallbacks or whole-service latency regress. |
| PyTorch sampling | Cosy defaults to this path. Filtering, penalty history, minimum-length stops and seeded sampling affect dispatch and output. | A fused sampler needs the same semantic/RNG contract, or a separately declared numerical/quality experiment. Do not conflate changing sampling with improving execution. |
| Estimator `torch.compile` | Off by default; `dynamic=True`; warms CFG batch 2 at 128 mel frames in both modes. Chunk-mask code remains eager; startup failure restores estimator forward. | Compare eager and compile in separate launches. Check actual prefix shapes, recompilation, graph breaks, startup fallback, runtime errors and memory. Warmup success does not guarantee later shapes or remove the outer Euler loop. |
| TensorRT estimator | Off by default and mutually exclusive with compile. Fixed two-row CFG engine executes request pairs separately even for a packed `2B` solve. Its exported streaming mask contract requires qualification. | Establish frozen-input streaming/buffered parity before accepting timing. If correct but c16 loses through pair serialization, a dynamic/batched engine is a separate design requiring profile ranges, per-row masks, CFG layout, workspace lifetime and numerical gates. A singleton win does not settle this choice. |
| Buffered Flow length grouping | Dynamic grouping already minimizes group count then padded work under merge limits; groups execute serially. | Compare valid and padded frame counts, actual group shapes and GPU time. Change grouping only when padding or fragmentation is material; preserve result-to-request mapping and fairness. |
| Streaming batching / growing hops | Packed causal Flow only for compatible groups; singletons use native Flow. Hops grow 25→50→100; readiness and peer waits control grouping. | Measure first-audio and continuity alongside throughput at both c1/c16. Larger hops or longer waits can improve batch size while violating latency goals. Preserve prompt/lookahead and final-tail semantics. |
| Streaming HiFT | Runs each request's accumulated history, with fixed source phase/noise and float64 F0. No evolving request cache exists. | Compatible-history batching is a narrower first candidate than replacing the whole vocoder. Incremental state or lower precision requires the full continuation/numerical proof in H2; arithmetic peculiarities are observable baseline behavior. |
| Reference cache / finalization | Bounded CPU cache with single-flight; GPU embedding preparation and float32 D2H/hash remain inside finalization ownership. | Compare cold unique references and deliberate warm-cache repeats separately. Change encoder threading against container quota, or cache-key preparation, only with conditioning identity and radix-prefix correctness preserved. |

The dated open-PR audit adds concrete alternatives to reconcile: #1861 already supplies buffered whole-solver graphs, #1933 supplies isolated-vocoder placement with fixed memory declarations, and #1693 supplies reference batching plus a tokenizer backend replacement. Their open status and benchmark claims do not establish H100 acceptance. #2110 changes timestep row shape and reports quality effects, while #2086/#2110 both change FIFO ingestion; resolve these proposed numerical/ordering baselines before attributing gains to another optimizer.

The first existing-path comparison is eager versus estimator compile, followed by TensorRT only after its mask/output contract passes. Keep Flow dtype, HiFT dtype, sampling, corpus and stage placement identical. Change only `--vocoder.factory.enable_dit_torch_compile` or `--vocoder.factory.enable_flow_estimator_trt` from the runbook's explicit eager launch; set the other false. Save resolved config and startup logs for every variant. Backend alternatives remain conditional experiments after actual dispatch and kernel dominance are established.

For each admitted alternative, report full-corpus c1 and c16 independently, both streaming/buffered modes in English, paired repeats, successful audio goodput, completion/first-audio tails, continuity, duration distributions, errors, memory and remote quality results. Profile only the small diagnostic cohort. Frozen codec/conditioning replay isolates acoustic numerical changes from AR sampling changes. If the implementation is demonstrably semantically wrong, split the correctness fix from the performance PR and establish a new qualified baseline before comparing gains.

Reconcile each candidate with [open PRs](../reports/17_open_prs.md). Reuse or narrow an existing change only after reading its actual head and contracts; do not duplicate an open implementation or assume its reported benchmark generalizes to this workload.
