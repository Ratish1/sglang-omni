# Sector 02: buffered acoustics

## Scope and evidence status

This report is a static, factual trace of the Fun-CosyVoice3 preprocessing, autoregressive (AR), buffered Flow/HiFT, causal streaming, accelerator, scheduler, state, and output mechanics at the repository baseline named in `RESEARCH_CONTRACT.md`. No tests, model executions, benchmarks, or package installations were run. Existing test source was read only as contract evidence. External CosyVoice, SGLang, ONNX Runtime, TensorRT, Matcha, Transformers, Whisper, torchaudio, and checkpoint behavior is an explicit boundary; this report records the calls and locally expected interfaces but does not claim their uninspected internals or byte-for-byte numerical equivalence.

## Factory graph and ownership

`FunCosyVoice3PipelineConfig` declares `preprocessing -> tts_engine -> vocoder`; preprocessing and AR are process-local, AR streams to the vocoder, and the terminal vocoder accepts a stream before its terminal payload. The defaults are preprocessing concurrency 8; AR bfloat16, 16 ONNX intra-op threads, token hop 25; vocoder bfloat16, admission 8,000 mel frames, length gap 384, padding budget 25%, batch size 16, wait 30 ms, TensorRT disabled, hop 25 growing to 100 (`config.py:32-106`). `CAPABILITIES` advertises reference audio, batch/streaming vocoder, CUDA graph, and torch.compile support (`__init__.py:1-17`).

The concrete call graph is:

1. `create_preprocessing_executor` validates positive concurrency and returns `SimpleScheduler(preprocess_cosyvoice3_payload, max_concurrency=N, abort_callback=cleanup_prepared_cosyvoice3_request)` (`stages.py:777-790`). With `N>1`, `SimpleScheduler` bridges its blocking inbox into an asyncio queue and runs synchronous preprocessing in `asyncio.to_thread`; result/error emission is per request (`simple_scheduler.py:264-310`). `ThreadedSimpleScheduler` is a related implementation but is not selected by this factory (`threaded_simple_scheduler.py:66-226`).
2. `create_sglang_tts_engine_executor` constructs `FunCosyVoice3EngineBuilder` and calls its inherited `build` (`stages.py:793-816`). The builder resolves `<checkpoint>/CosyVoice-BlankEN`, establishes SGLang defaults, loads `llm.pt` on CPU, installs the custom weights, creates text/speech/speaker encoders, registers the preprocessing context, creates the model runner and request/result adapters, then points the runner's streaming outbox at the AR scheduler outbox (`engine_builder.py:26-143`; `engine_factory.py:56-240,335-410,436-519`). `create_tts_engine_executor` is the same function object (`stages.py:819`).
3. `create_vocoder_executor` rejects a nonpositive admission budget and simultaneous DiT compile/TRT, resolves device and checkpoint, maps the Flow autocast string, loads external CosyVoice Flow and HiFT, optionally attaches TRT or compiles the DiT, constructs `_CosyVoice3Vocoder`, then wraps it in `FunCosyVoice3StreamingVocoderScheduler` with the admission and hop settings (`stages.py:1245-1311`). The wrapper inherits non-streaming batching and streaming lifecycle from `StreamingSimpleScheduler` and `StreamingVocoderBase` (`streaming_simple_scheduler.py:34-551`; `streaming_vocoder.py:84-506`).

## Preprocessing and AR entry contracts

`preprocess_cosyvoice3_payload` builds `FunCosyVoice3State`, obtains reference conditioning through a single-flight `ReferenceEncodeService`, serializes final model prompt construction under `_PREPROCESSING_FINALIZE_LOCK`, stores Flow tensors in state, emits a marker payload, and retains the full `CosyVoice3PreparedRequest` in a process-local dictionary keyed by request id (`request_builders.py:704-739`). Abort removes that entry (`request_builders.py:390-392`). The reference service caches at most 256 entries / 128 MiB, merges concurrent identical keys, waits up to 130 seconds, and uses non-batched `encode_one` because this hook does not override `can_encode_batch` (`request_builders.py:348-380`; `reference_encoder.py:130-420`). Stored artifacts are detached CPU clones; the stage cache accounts tensor bytes and performs LRU eviction (`request_builders.py:302-330`; `stage_cache.py:71-184`).

Reference audio is loaded independently at 16 kHz and 24 kHz. The 16 kHz path feeds CAMPPlus and speech-tokenizer ONNX; the 24 kHz path feeds Matcha mel extraction. `_align_flow_prompt` chooses `P=min(speech_tokens, floor(mel_frames/2))`, then returns tokens `[:P]` and mel frames `[:2P]`, contiguous (`request_builders.py:277-300,419-433,556-575`). The local encoder calls are `whisper.log_mel_spectrogram(..., n_mels=128)` followed by speech-tokenizer `InferenceSession.run`; Kaldi `fbank(num_mel_bins=80,dither=0)` followed by CAMPPlus `InferenceSession.run`; and `matcha.utils.audio.mel_spectrogram(n_fft=1920,num_mels=80,sampling_rate=24000,hop_size=480,win_size=1920,fmin=0,fmax=None,center=False)` (`utils.py:42-187`).

`_prepare_cosyvoice3_request` tokenizes target text, records its token count before adding the prompt text, embeds text with `model.text_embed_tokens`, and constructs `[SOS embedding, text embedding, TASK embedding, optional reference speech embeddings]`. CAMPPlus speaker embedding is not inserted into this LLM prompt; it is retained for Flow (`request_builders.py:626-701`; `utils.py:190-219`). The embedding rows are copied to float32 CPU and hashed to synthetic cache ids (`request_builders.py:617-623`). `build_sglang_cosyvoice3_request` consumes the prepared entry exactly once; creates `SamplingParams` with default sample temperature 0.7, top-p 0.8, top-k 20, repetition penalty 1.21; suppresses all 200 control ids as stop ids; derives default maximum `min(2048,20*max(target_text_tokens,1))` and minimum `min(2*target_text_tokens,max_new_tokens)`; and builds the SGLang `Req` plus scheduler data (`request_builders.py:742-817`).

The custom model uses Qwen2 as backbone, speech-token embeddings for decode input, and a 6,761-output speech decoder. Extend/prefill selects the last hidden row per sequence before logits (`sglang_model.py:26-124`). The runner passes prebuilt prompt embeddings for prefill, samples before both post-prefill and post-decode hooks, and calls `next_token_ids.tolist()` once for the whole batch. IDs below 6,561 become one-element CPU `long` tensors; all control ids are skipped (`model_runner.py:48-116`). For streaming requests, the AR runner buffers 28 tokens for the first flush (`25+3`) and 25 thereafter, attaches Flow prompt tensors only to the first stream message, and force-flushes any remainder at request finish (`model_runner.py:118-183`; `streaming.py:97-107`). Terminal adaptation stacks codes, moves them to CPU, records prompt/completion counts and elapsed wall time, and serializes state (`request_builders.py:820-850`).

## Non-streaming buffered admission and exact grouping

The vocoder scheduler distinguishes streaming from non-streaming via `bool(payload.request.params["stream"])` (`scheduling/streaming_vocoder.py:164-171`). Only non-streaming payloads enter the cost-limited terminal batch path. Starting from the first request, `_collect_new_request_batch` waits until the 30 ms deadline, stops at 16 items, and evaluates each request's nonnegative cost. The first request is always admitted even if its own cost exceeds the budget. A later request for which `accumulated_cost + request_cost > 8000` is pushed to the front of the pending deque and ends collection (`streaming_simple_scheduler.py:244-308`). The cost is

`scheduler_cost_i = (prompt_token_count_i + generated_token_count_i) * flow.token_mel_ratio`

(`stages.py:1175-1181`). The default ratio imported for stream math is 2, while buffered cost reads the loaded Flow object's `token_mel_ratio` (`streaming.py:14-24`; `stages.py:1175-1177`). A batch-function exception is emitted independently to every still-active request; an output-count mismatch is likewise emitted to each (`streaming_simple_scheduler.py:383-446`).

`decode_batch` then constructs `_PreparedFlowRequest(index,sample_rate,flow_input,total_mel_frames)` for each admitted item and independently repartitions that scheduler batch (`stages.py:994-1036`). Let sorted request lengths be `L_0 <= ... <= L_(n-1)`, with original index breaking ties, and `W=sum L_i`. `adaptive_flow_requests_grouping` considers contiguous partitions of this sorted order. Every candidate group `[a,b)` must satisfy `L_(b-1)-L_a <= flow_merge_max_gap_frames`. Its padded work is `(b-a)*L_(b-1)`. Dynamic programming minimizes the lexicographic tuple `(total padded work, maximum group gap across the partition, tuple of group end indices)` for a fixed group count. It tries group counts from 1 through `n` and returns the first optimum satisfying

`(total_padded_work / W - 1) * 100 <= flow_merge_pad_budget_percent + 1e-9`.

Defaults are a 384-frame maximum within-group length gap and 25% aggregate padding budget (`stages.py:830-912`). Flow groups execute sequentially in the returned order (`stages.py:1010-1033`).

## Packed Flow tensors, CFG, noise, and Euler solver

Each `FlowBatchInput` must contain target tokens `[1,T]` with `T>0`, prompt tokens `[1,P]`, prompt features `[1,2P,C]`, and embedding `[1,S]`; feature width must equal `flow.output_size`, and `S` is checked against the speaker affine input width when exposed (`stages.py:101-131`). `_pack_flow_inputs` obtains device/dtype from the first Flow parameter. It left-aligns concatenated prompt then target ids into int32 `[B,max(P+T)]`, zero-pads, and builds boolean `[B,max_tokens,1]` validity. Prompt features become `[B,max(2P),C]` in Flow dtype, and embeddings concatenate to `[B,S]` in Flow dtype. Length tensors are int64 on the Flow device (`stages.py:93-199`).

`_generate_flow` normalizes speaker embeddings along dimension 1 before `spk_embed_affine_layer`. Token ids are clamped at zero, embedded, and multiplied by the token mask. Final/buffered inference calls the pre-lookahead layer on the full token sequence. Non-final causal inference removes lookahead from each row; for mixed lengths it slices each row's real tail rather than padded tail and right-pads returned hidden sequences to a shared body length (`stages.py:202-248,340-409`). Hidden states repeat each token `token_mel_ratio` times and transpose to `mu=[B,C,M]`. The mel mask is `[B,1,M]`, with true/one positions below each effective mel length. `cond` is zero except `cond[i,:,:prompt_frames_i]`, which receives the transposed prompt features (`stages.py:340-383`).

Noise comes from the same prefix of `decoder.rand_noise[0,:,:M]` for every request: it is converted to `mu` device/dtype, expanded to batch, and cloned. `M` beyond the stored noise buffer raises. Time uses 11 points from 0 to 1 in `mu` dtype/device; a `cosine` scheduler maps them to `1-cos(t*pi/2)` (`stages.py:384-409`).

For each of 10 Euler intervals, `_solve_flow_euler` materializes `x_in`, `mask_in`, `mu_in`, `spks_in`, and `cond_in` with leading dimension `2B`, plus scalar-shaped `t_in=[1]`. Both CFG halves receive the same current `x` and mask. Only rows `[0:B]` receive `mu`, speaker embedding, and conditioning; rows `[B:2B]` remain zero for those values. If estimator output is `(conditional,unconditional)`, the update is

`x <- x + dt * ((1 + inference_cfg_rate) * conditional - inference_cfg_rate * unconditional)`.

The updated `t` and next `dt` follow the possibly transformed time grid. The solver returns float32 (`stages.py:251-298`). Buffered outputs crop each row from its own prompt-frame count through `(P+T)*ratio`, assert `[1,output_size,T*ratio]`, and retain device tensors (`stages.py:412-431,494-509`). Causal packed output instead subtracts the lookahead token count from both target and combined lengths before cropping (`stages.py:512-532`). Existing static tests pin the two-half CFG layout, per-row masks/conditioning/crops, reused noise prefix, mixed lengths, causal lookahead removal, and TRT pair chunking (`tests/unit_test/fun_cosyvoice3/test_flow_batch.py:1-392`); they were not executed here.

## Estimator dispatch, autocast, compilation, and TensorRT

Flow groups execute under `torch.autocast(device_type=current_platform.device_type,dtype=compute_dtype,enabled=compute_dtype is not None)`. Factory strings map float32 to disabled autocast, float16 to fp16, and bfloat16 to bf16; bfloat16 is the pipeline default. The external `CosyVoice3(checkpoint_dir, fp16=(dtype=="float16"))` flag is only true for float16 (`stages.py:53-57,646-669,1017-1025,1245-1311`). A PyTorch `nn.Module` estimator is invoked through external `decoder.forward_estimator(...,streaming=...)`; a non-module estimator is invoked through local `execute_flow_estimator` (`stages.py:434-453`).

Opt-in compile sets Inductor graph caching and Dynamo cache limits to 1,024 where available. It replaces both imported CosyVoice chunk-mask references with `torch.compiler.disable(add_optional_chunk_mask)` once, compiles the bound estimator `forward` with `dynamic=True`, and warms three calls each at `[2,80,128]` for `streaming=False` and `True` under inference mode and the selected autocast. Non-module estimators are skipped. Any compile/warmup exception restores the original eager `forward` and returns false (`stages.py:672-774`). Existing compile tests statically encode those call shapes, grad mode, and restoration behavior (`tests/unit_test/fun_cosyvoice3/test_dit_compile.py:1-142`).

Opt-in TRT requires a CUDA device, CUDA platform/runtime availability, and an ONNX candidate in priority order fp32, generic, autocast-fp16. It retains the original PyTorch estimator as fallback, builds a `FlowEstimatorTRTModule`, deletes the registered estimator child, and assigns the module wrapper (`stages.py:543-580`). Compile and TRT are rejected together in both config validation and factory construction (`config.py:14-29,97-106`; `stages.py:1271-1275`).

TRT has fixed CFG batch 2 and mel width 80, with dynamic time profile `[4,500,5000]` min/opt/max. Its plan key includes ONNX absolute path, size, integer mtime, device name, TRT version, batch, and profile. Cache defaults to `~/.cache/sglang-omni/cosyvoice3_trt` unless `COSYVOICE3_TRT_CACHE` is set. FP16-named/autocast ONNX is strongly typed with fp16 I/O; otherwise I/O is fp32 and the legacy FP16 tactic flag is used only when exposed. Workspace is 8 GiB (`flow_estimator_trt.py:17-30,38-199`).

`FlowEstimatorTRT` owns a blocking queue of execution-context/CUDA-stream pairs, one by default (`flow_estimator_trt.py:209-249`). `_enqueue_once` requires the exact canonical CUDA device, exact `[2,80,T]` x/mu/cond, `[2,1,T]` mask, `[2]` time, `[2,80]` speakers, and an in-profile `T`. The dedicated stream first waits on the caller stream. Inside it, all six inputs are converted to engine I/O dtype and contiguous, output is allocated like converted x, input shapes and tensor addresses are bound by engine tensor order, and `execute_async_v3` is issued. Every CUDA tensor records the dedicated stream. The caller stream then waits on the dedicated stream, output records the caller stream, and output converts back to x dtype. The context/stream pair returns to the pool in `finally` (`flow_estimator_trt.py:252-300`). These are stream dependencies; the local path contains no explicit host/device synchronize call.

Packed CFG is `[cond_0...cond_(B-1), uncond_0...uncond_(B-1)]`. When `2B` exceeds `max_batch`, `execute_flow_estimator` slices request pairs as `[conditional slice, corresponding unconditional slice]`, executes chunks of `max(1,max_batch//2)` requests, and writes each half back to its original position. A broadcast `[1]` timestep is expanded to `2B` first (`flow_estimator_trt.py:319-368`). The production engine's max batch is 2, so a packed request batch is submitted as one CFG request pair per enqueue for every Euler evaluation. `FlowEstimatorTRTModule` uses TRT only for in-profile T; outside the profile it calls the retained PyTorch estimator with the original streaming flag, or raises when no fallback exists. In-profile TRT discards `streaming` because the local comment states the ONNX attention is frozen (`flow_estimator_trt.py:371-431`). Existing TRT tests pin input shape checks, CFG-pair slicing, timestep expansion, wrapper recognition, and profile fallback (`tests/unit_test/fun_cosyvoice3/test_flow_estimator_trt.py:1-281`); they were not executed here.

## Independent HiFT grouping and waveform production

After each Flow solve, its mel list is repartitioned independently for HiFT. `_group_by_padding_waste` sorts pairs by mel length. For a current group with actual-length sum `S` and candidate item length `l`, it starts a new group when

`max(current_longest,l) * (current_group_size + 1) > hift_max_padding_waste * (S + l)`.

The default multiplier is 1.5 (`stages.py:915-936`). A singleton calls `_mel2wav` directly. A multi-item group right-zero-pads mel tensors to the longest length (or concatenates without pad if equal), calls external `hift.inference(speech_feat=padded,finalize=True)` once under the independent HiFT autocast, detaches the returned batch, and crops each waveform to `mel_length_i * samples_per_mel_frame` before `.cpu()` (`stages.py:1183-1219`). HiFT autocast defaults to disabled float32 even while Flow defaults to bf16. `samples_per_mel_frame = istft_params["hop_len"] * product(upsample_rates)` and missing/false metadata raises (`stages.py:593-608,940-979`). Load-time preparation folds all parametrizations, including weight norm, with `leave_parametrized=True` (`stages.py:583-622`).

Each Flow group and its HiFT subgroups finish before the next Flow group starts. Results are placed back by original request index, so the sorted/grouped execution order does not change output order (`stages.py:994-1036`).

## Streaming causal path

Streaming messages bypass buffered cost admission. New streaming payload coalescing takes already queued distinct request ids up to the batch cap without the non-streaming 30 ms collection loop; stream chunks likewise collect distinct ids while deferring repeated chunks from the same request (`streaming_vocoder.py:193-287`). The subclass additionally waits up to 30 ms for a compatible first-hop or follow-up peer when it can identify one (`streaming_vocoder.py:289-434`). First hops have priority. They group by `hop+lookahead`; follow-ups group by `(current_hop_len,token_offset)`, then cap at max batch (`streaming_vocoder.py:566-602`).

Prompt token/features are normalized, then padded to a multiple of the configured initial hop by repeating their last token/frame; empty prompts use zeros. Feature padding is `token_pad*2`. After latch, only shapes are checked on a later payload/chunk copy; values are not compared. `prompt_pad` is set to zero because actual prompt tensors were padded (`streaming.py:110-154`; `streaming_vocoder.py:492-524`). A non-final step is ready at `len(tokens) >= token_offset + hop + 3`. After each successful causal hop, hop grows by factor 2 up to 100 unless growth is disabled (`streaming.py:49-94`; `streaming_vocoder.py:130-135,556-564`).

For `B>1`, a step constructs packed `FlowBatchInput` rows from all generated tokens through `token_offset+hop+3`, calls `FunCosyVoice3Flow.inference_causal`, slices each returned mel at `token_offset*2`, then calls HiFT separately for each request through `_hift_delta`; HiFT is therefore not cross-request batched on the streaming path (`streaming_vocoder.py:604-696`). For `B=1`, the wrapper calls external native `flow.inference(token,token_len,prompt_token,prompt_token_len,prompt_feat,prompt_feat_len,embedding,streaming,finalize)`, slices at `token_offset*2`, and calls HiFT (`stages.py:1066-1114`; `streaming_vocoder.py:698-795`). Non-final HiFT calls use `finalize=False`; terminal remainder uses `finalize=True` and locally defaults Flow `streaming=False` (`streaming.py:21-26`; `streaming_vocoder.py:716-755`).

`_hift_delta` prepends the complete retained `hift_mel` history to new mel, calls external HiFT, drops the already-emitted sample prefix `speech_offset`, returns the remaining waveform as detached CPU, and retains detached mel plus the new full waveform length for the next call (`stages.py:1131-1144`). On stream completion, ready causal hops drain first, then all remaining tokens are finalized. If no waveform has ever been emitted, the base requests a full non-streaming fallback decode. It then emits any last audio chunk followed by a metadata-only terminal result, records completion, and releases token/prompt/mel references (`scheduling/streaming_vocoder.py:225-299`; `models/fun_cosyvoice3/streaming_vocoder.py:716-859`). Abort/error and scheduler stop also clear those resources; late chunks for aborted/completed ids cannot recreate state (`scheduling/streaming_vocoder.py:145-162,251-299`).

## Copies, synchronization, state mutation, and output contract

The explicit transfer/synchronization points are:

- Reference cache storage detaches, moves to CPU, and clones tensors; state codec `tensor_list` calls detach/CPU/list. Restoration leaves those fields as lists until callers use `torch.as_tensor` (`request_builders.py:154-157,302-330`; `pipeline_state.py:65-92,204-282`).
- AR collection uses one batched `next_token_ids.tolist()` device-to-host boundary. Terminal AR result concatenation calls `.cpu()` (`model_runner.py:96-116`; `request_builders.py:820-850`).
- Flow packing copies prompt/target ids, prompt features, and embeddings to the Flow device/dtype as it fills new destination tensors (`stages.py:134-199`). Solver and split outputs stay on device.
- Buffered HiFT waveform crops call `.cpu()` per result. Streaming `_hift_delta` calls `.detach().cpu()` per emitted delta while retaining mel on device (`stages.py:1131-1144,1195-1219`).
- `audio_waveform_payload` converts tensor audio with `detach().float().cpu().numpy()`, flattens unless channel retention is requested, makes a contiguous float32 NumPy array, and stores raw bytes, shape, and dtype (`audio_payload.py:20-54`).
- TRT uses CUDA stream waits and `record_stream` without an explicit host synchronize (`flow_estimator_trt.py:252-300`). Flow debug timing queries its end event and skips the record if still pending; it never waits. The query occurs after HiFT output has reached host for that Flow group (`stages.py:301-336,477-491,994-1036`).

Buffered `store_result` rejects missing audio, clears `state.audio_samples` and `state.audio_codes`, sets sample rate, replaces `payload.data` with serialized state, then adds waveform bytes, sample rate, modality `audio`, and optional usage (`stages.py:1221-1242`). Streaming chunks carry serialized waveform data and outgoing metadata `{modality: "audio"}`; terminal streaming results carry modality, sample rate, and optional usage but no full waveform (`scheduling/streaming_vocoder.py:347-355`; `models/fun_cosyvoice3/streaming_vocoder.py:825-849`).

## Errors, cancellation, drain, and observability

Shape/alignment errors are raised before Flow execution; noise overflow, unexpected Flow output shape, missing HiFT stride metadata, missing prompt conditioning, no generated codes, accelerator conflicts, unsupported dtype, and TRT build/enqueue/profile-without-fallback errors are explicit exceptions in their respective paths. Non-streaming batch errors are fanned out to each active request. A coalesced streaming-step exception emits the same error to every participant, marks each aborted, clears resources under the state lock, and runs external abort cleanup afterward (`streaming_vocoder.py:451-465`; `scheduling/streaming_vocoder.py:488-506`). `stream_done` received before the payload is retained and processed once the payload arrives (`streaming_simple_scheduler.py:470-519`).

Existing logs cover checkpoint/weight load, weight-norm folding, compile success/fallback, TRT build/load/profile miss, reference-cache stats at most once per 60 seconds, first/follow-up Flow batch size, scheduler compute failures, and optional Flow solve time. Solve timing is only created when the module logger has DEBUG enabled. CPU uses `perf_counter`; accelerator events are queried without waiting, and pending measurements are discarded (`stages.py:301-336,477-491`; `test_flow_solve_observability.py:1-175`). There are no local counters for Flow admission rejects, selected adaptive partition, padding frames, HiFT subgroup sizes, TRT context-pool wait, or per-phase transfer bytes in the inspected code; this is a statement of inspected observability only.
