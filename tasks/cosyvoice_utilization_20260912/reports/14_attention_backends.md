# Sector 14 — SGLang Qwen2 attention backends

## Scope and evidence boundary

This report traces the SGLang-side attention interface reached by the repository's Qwen2 model and the complete `flashinfer_backend.py` and `triton_backend.py` implementations. It describes static dispatch and call contracts. It does not establish which backend an H100 process actually selected: the selected prefill/decode names enter through runtime configuration, and no launch record or live process was examined.

The primary owners are `flashinfer_backend.py` (1–2540) and `triton_backend.py` (1–2255). Direct dispatch dependencies were read completely: `base_attn_backend.py` (1–341), `radix_attention.py` (1–657), `qwen2.py` (1–769), `attention_registry.py` (1–542), and `attention_backend_setup.py` (1–257).

## Qwen2 to backend call boundary

`Qwen2Attention.__init__` partitions Q heads by TP, partitions or replicates KV heads depending on their relation to TP size, sets `head_dim`, `q_size`, `kv_size`, and `head_dim**-0.5` scaling, creates the QKV and output projections and rotary embedding, then constructs `RadixAttention(num_heads=self.num_heads, head_dim, scaling, num_kv_heads=self.num_kv_heads, layer_id, quant_config, prefix)` (`qwen2.py:126–200`). Its forward projects hidden states, splits the packed result into Q/K/V, applies rotary embedding to Q/K, calls `self.attn(q, k, v, forward_batch)`, and output-projects the result (`qwen2.py:202–213`). Qwen2 supplies no custom mask, sinks, score modifier, cross-attention flag, sliding-window size, or non-default `AttentionType` at this call site.

`RadixAttention.__init__` stores TP-local Q/K/V head counts, QK and V dimensions, scaling, layer/cache identity, mask-related flags and cache scales; its defaults are decoder attention, no cross attention, and `sliding_window_size=-1` (`radix_attention.py:98–155`). `RadixAttention.forward` reshapes K/V to `[tokens, tp_kv_heads, head_dim]` when present (`157–175`). In an extend forward with a tensor-core-piecewise context, it can cross a registered custom-op boundary: it allocates output, narrows padded batches to real tokens inside `_unified_attention_with_output_impl`, calls `get_attn_backend().forward(...)`, restores the original batch cache-location and position fields, copies into the preallocated output if necessary, and zeros the padded tail (`157–298`, `301–423`, `428–513`). Without that context, and for decode, it calls `get_attn_backend().forward(...)` directly (`289–298`).

`AttentionBackend.forward` owns mode dispatch: idle returns an empty correctly shaped output, decode calls `forward_decode`, NPU mixed mode calls `forward_mixed`, and every other mode calls `forward_extend` (`base_attn_backend.py:249–291`). Thus target verification and ordinary prefill/extend reach each backend's extend implementation.

The setup layer resolves a draft-worker override to one backend name for both phases; otherwise it reads the runtime context's `(prefill, decode)` pair (`attention_backend_setup.py:158–178`). Equal names build one backend. Unequal names build the two named full-attention implementations and place them in `HybridAttnBackend`, then apply model wrappers once (`181–235`). `_build_full_attention_backend_from_str` indexes `ATTENTION_BACKENDS` and invokes its factory (`251–257`). The registry's `flashinfer` factory creates `FlashInferAttnBackend` for non-MLA models and creates an EAGLE plan stream when needed (`attention_registry.py:50–74`); the `triton` factory rejects encoder-decoder models before constructing `TritonAttnBackend` (`183–191`). These factories expose supported choices; they do not prove the value selected on a particular H100 run.

## Shared metadata lifecycle

The base contract separates eager initialization, host/dynamic work outside a CUDA graph, and graph-recordable static-shape work inside capture (`base_attn_backend.py:36–130`). Default eager initialization calls `init_forward_metadata_out_graph` and then `init_forward_metadata_in_graph` (`88–94`). The in-graph contract excludes host reads such as `.item()`, `.cpu()`, `.tolist()`, and dynamic allocation (`118–130`). Both subject backends implement their dynamic table construction outside the graph and use preallocated buffers for graph replay. Both return `1` as the padded graph sequence-length fill value (`flashinfer_backend.py:1307–1308`; `triton_backend.py:1293–1294`).

The model layer does not construct page tables or masks. `ForwardBatch`, speculative input objects, the request-to-token mapping, and `KVIndexTranslator` supply request rows, sequence lengths, prefix lengths, optional custom masks, and translated read/write identity. Each backend turns those inputs into its kernel-facing metadata.

## FlashInfer backend

### Construction, prerequisites, and layout

FlashInfer symbols are imported only when `is_flashinfer_available()` is true: paged decode, paged prefill, ragged prefill, fast decode planning, and cascade state merge (`flashinfer_backend.py:75–112`). Because the class names are referenced by construction, using this backend requires the external `flashinfer` package to have supplied them. `_safe_merge_state` uses FlashInfer cascade merge when its derived block thread count stays at or below 1024 and otherwise calls the in-tree Triton merge implementation (`93–112`).

`FlashInferAttnBackend.__init__` resolves the request/token pools, index translator, optional SWA pool, KV-cache attention access for each phase, cache dtype, head counts, context/page size, and wrapper multiplicity (`293–395`). The exact class validates FlashInfer KV-cache access only for a phase whose resolved backend name is `flashinfer` (`333–350`). For a Qwen2 architecture it sets the process environment wrapper's FlashInfer workspace size to 512 MiB; deterministic mode later forces tensor-core decode, sets split tile defaults, disables CUDA-graph KV split for decode, and sets it to 2 GiB (`396–428`). This is initialization behavior, not evidence of backend selection.

All wrappers use FlashInfer layout string `NHD` (`482–514`). The general ragged prefill wrapper selects backend `auto`, except SM100 without TC-piecewise graph selects `cutlass`; paged prefill uses `fa2`, and decode uses `fa2` with the computed tensor-core choice (`476–514`). Paged wrappers are planned with page size `1` in this file (`1711–1822`, `2132–2326`), while generated KV indices map logical request positions to cache-slot/page identities. The backend retains model `page_size` for page-table construction and dequant-workspace alignment (`377–378`, `873–946`).

The shared or private byte workspace is allocated on `model_runner.device`; `kv_indptr`, `kv_last_page_len`, and, unless prefill is skipped, `qo_indptr` are device tensors sized from graph maximum batch size (`430–474`). One wrapper serves ordinary self attention. Sliding-window or encoder-decoder configurations create two wrappers, selected per layer by `_get_wrapper_idx`: window layers use wrapper 0 and full layers wrapper 1; normal versus cross attention similarly uses 0 versus 1 (`386–394`, `1530–1539`).

### Eager metadata and page-table ownership

`init_forward_metadata` gets the batch's translated `KVIndexTable` and an SWA write location if applicable (`953–960`). Decode calls `FlashInferIndicesUpdaterDecode.update`, then stores the planned wrappers in `DecodeMetadata` (`961–975`). Target verification plans paged prefill with speculative metadata and no ragged path (`976–994`). Other extend modes determine whether ragged processing is allowed, prepare multi-item and optional FP4 dequant metadata, call the prefill updater, and save `PrefillMetadata` (`995–1049`). Multimodal and multi-item scoring force paged prefill; otherwise ragged is used unless deterministic, TC-piecewise graph, or `SGLANG_FLASHINFER_USE_PAGED` prevents it (`998–1014`).

The decode updater builds `kv_indptr` by cumulative sequence lengths, allocates or reuses `kv_indices`, and calls `create_flashinfer_kv_indices_triton` over `KVIndexTable.ids`, row ids/stride, lengths, and optional start offsets (`1711–1757`). Speculative decode may supply `kv_indptr` and `kv_indices` directly (`1758–1760`). Sliding-window metadata clamps length to `window+1` and advances start offsets; full attention uses complete lengths (`1618–1669`). Cross-attention wrapper 1 uses encoder lengths starting at zero (`1671–1709`). If a static full-id table feeds an SWA pool, indices are translated in place; already translated SWA source tables are not translated again (`1726–1769`). `begin_forward` receives the indptr, indices, last-page lengths, maximum planned heads, Q/KV dtypes, split settings, and page size 1 (`1771–1825`).

The prefill updater constructs `qo_indptr` from extend lengths and `kv_indptr` from either prefix lengths (ragged cached side) or full sequence lengths (paged side) (`1888–1937`, `2132–2202`). Sliding-window handling constructs trimmed prefix lengths and, for ragged prefix merging, `_build_swa_prefix_custom_mask`; paged-only ordinary SWA instead passes `window_left` to planning (`1939–2074`). Cross attention selects full decoder history for wrapper 0 and encoder-only KV for wrapper 1, forwarding a cross-attention custom mask only to wrapper 1 (`2076–2130`). Speculative inputs own generation of their prefill KV indices, indptrs, QO indptrs, and custom mask (`2204–2225`). Multi-item parameters suppress the generic custom mask and pass specialized prefix/item-position arguments (`2247–2262`). The paged wrapper's `begin_forward` receives `qo_indptr`, `kv_indptr`, `kv_indices`, last-page length, head geometry, page size 1, dtype, custom mask, split policy, and any multi-item data (`2307–2326`).

### Prefill and decode execution

`forward_extend` selects the layer's planned wrapper and cache write target, makes Q contiguous, obtains either the ordinary per-layer KV buffer or a dequant workspace, and writes K/V before paged attention when requested (`1311–1365`). Paged execution passes reshaped Q plus the KV cache, with causal false only for cross attention or encoder-only attention; it passes layer scale, logit cap, sliding-window setting, and scalar cache descales (`1367–1394`). Ragged no-prefix execution attends directly over current K/V (`1415–1426`). Ragged prefix reuse computes current-chunk attention and paged cached-prefix attention with LSEs and merges the states, then writes K/V (`1428–1467`). Output is flattened to `[tokens, tp_q_heads * head_dim]` (`1469`).

`forward_decode` writes supplied K/V first, obtains ordinary or decode-dequant KV storage, calls the selected decode wrapper with contiguous reshaped Q, layer scale/cap, and cache descales, and flattens output (`1472–1528`). The wrapper plan already owns page indices and sequence boundaries; the layer call supplies no mask argument.

### CUDA graph state

`init_cuda_graph_state` allocates capture tables, fixed KV-index buffers, optional SWA write targets, custom-mask and indptr buffers (`1051–1094`). Decode wrappers bind those buffers at construction (`1096–1109`). Prefill graph wrappers bind QO/KV indptr, KV indices, last-page lengths and, only when a custom mask exists at capture, custom-mask and mask-indptr buffers (`1128–1157`). Plain full-graph EXTEND gets a dedicated sized workspace and fixed request-slot/index buffers (`1159–1267`). `_prepare_cuda_graph_metadata` constructs and stores wrapper sets by forward mode (`1269–1305`).

On capture or replay, `init_forward_metadata_out_graph` rebuilds the translated index table and updates the appropriate fixed wrapper buffers outside the graph (`699–806`). After the first real capture plan, eligible FA2 decode wrappers are rebound to `fast_decode_plan`; eligible single-wrapper draft-extend and DFLASH verify wrappers are rebound to `fast_prefill_plan` (`808–853`). `fast_prefill_plan` requires CUDA-graph mode, FA2, a cached module from the capture plan, host QO/KV indptr and lengths, and no custom mask; it copies device inputs into fixed buffers then calls the cached module's lower-level plan (`179–290`, `2264–2301`). SWA write targets are refreshed into a capture-stable buffer before replay (`855–871`).

`FlashInferMultiStepDraftBackend` owns one backend per draft step except the last, preallocates per-step indptrs, generates speculative KV indices once, and installs the step's slices into `spec_info` before initializing each child backend (`2329–2452`). Its graph path allocates fixed indices and delegates child graph state/metadata (`2454–2491`).

## Triton backend

### Construction, prerequisites, and metadata layout

`TritonAttnBackend.__init__` lazily imports the in-tree decode, extend, unified-extend, verify, and unified-index-building kernels and wraps them with `torch.compiler.disable` (`triton_backend.py:156–198`). It records request/KV pools, translator, page size, speculative geometry, attention head geometry, device/core count, split policy, optional SWA state, DCP state, and fixed metadata buffers (`200–376`). Unlike the registry's FlashInfer factory, the Triton factory explicitly rejects encoder-decoder models (`attention_registry.py:183–191`), although the backend contains some cross-attention-related causal checks.

`ForwardMetadata` owns decode partial-result buffers, QO/KV indptr and indices, mask and mask indptr, separate window tables/splits/offsets, optional SWA logits/write locations, unified-pool physical write locations, and optional lean-decode scratch (`triton_backend.py:117–144`). `get_num_kv_splits` either fills a static count, derives deterministic splits from fixed tile size, or calls `get_num_kv_splits_triton` using sequence/head/device-core geometry (`378–425`).

### Eager metadata and page-table ownership

`init_forward_metadata` builds all eager metadata (`754–1018`). Decode obtains an index table, constructs complete or DCP-sharded KV indptr/indices, optionally constructs a window table, allocates fp32 split-logit/LSE tensors and split counts, and allocates lean-decode partial buffers and locks (`768–870`). Speculative multi-step decode can provide KV indptr/indices directly (`815–817`). Target verify creates fixed-stride QO indptr, complete KV pages, optional window pages/offsets, uses `spec_info.custom_mask`, constructs per-request mask offsets as `draft_tokens * (seq_len + draft_tokens)`, and sets maximum extend length to the actual draft window (`871–930`). Ordinary extend maps cached prefixes into KV indices, builds QO indptr from extend lengths, and computes maximum extend length (`932–985`).

`_fill_kv_indptr_and_indices` cumulatively encodes lengths and gathers slot/page ids from the translator's index table (`460–479`). `update_sliding_window_buffer` truncates each sequence to `min(seq_len, window)`, gathers from `sliding_window_read_ids`, and translates only static, non-translated tables feeding `BaseSWAKVPool` (`2203–2255`). DCP metadata shards lengths and generates rank-owned indices (`427–458`).

### Prefill/extend execution and masks

`forward_extend` obtains or allocates output and either reads K/V back at the output locations or writes newly supplied K/V first (`1338–1403`). `_set_kv_buffer` handles DCP rank ownership; ordinary writes can include both virtual/full and SWA locations in `KVWriteLoc` (`1305–1336`). Causality is false for cross attention, encoder-only, or allowed decoder-bidirectional extend; otherwise it is true (`1405–1416`). DCP, deterministic unified, optional verify-specialized, and ordinary two-stage paths then diverge.

The ordinary path selects window or full KV metadata from the layer's `sliding_window_size`, derives descales, optionally calls a verify kernel for eligible target-verify metadata, and otherwise calls `extend_attention_fwd` (`1441–1535`). The kernel receives current K/V, persistent cache buffers, QO and KV indptr/indices, the custom mask and mask indptr, causal flag, maximum extend length, layer scale/cap, window size/offset, page size, and optional score modifier/auxiliary tensors. Thus `spec_info`/metadata construction owns tree/custom-mask content and offsets; the backend owns routing those tensors to the kernel; the imported kernel owns mask application.

Deterministic `_forward_extend_unified` constructs one index sequence from cached-prefix indices and current-output cache locations, derives prefix lengths and optional window start positions, and calls `extend_attention_fwd_unified` with the same causal/custom-mask controls (`1680–1826`). DCP extend separately computes current-token and rank-sharded-prefix states, all-gathers query heads, reduces/merges by LSE, and rejects sinks, custom masks, sliding windows, and score modifiers (`1537–1678`).

### Decode execution

`forward_decode` reshapes Q, allocates output, writes the current K/V to the cache, selects full or window KV tables, chooses the V-dimension-compatible fp32 logits buffer, and resolves lean-decode activation (`1828–1945`). DCP decode all-gathers Q heads, invokes the decode kernel with rank-local page metadata and partial buffers, then cross-rank merges by LSE (`1947–1994`). The non-DCP call passes Q, persistent K/V buffers, KV indptr/indices, fp32 logits/LSE scratch, split counts, scaling/descales, optional cap/sinks, MLA/PDL/page-size flags, score modifier/auxiliary tensors, and lean scratch (`1996–2024`). Decode has no custom-mask field in `ForwardMetadata`; sequence visibility is expressed by its KV indptr/indices and optional window table.

### CUDA graph state

`init_cuda_graph_state` preallocates split logits/LSE, lean scratch, split counts, KV indices, optional verify mask, optional window indices/splits/offsets, optional SWA write targets, optional unified-pool physical write targets, and capture read tables (`1020–1144`). `_apply_cuda_graph_metadata` rebuilds the translator's index table into fixed storage and updates decode, verify, or draft-extend buffers (`1251–1291`). `_build_cuda_graph_forward_metadata` returns views of the same address-stable tensors for decode, verify, or draft extend (`1146–1249`). `init_forward_metadata_out_graph` performs these updates before capture/replay and refreshes write locations; on replay it reuses the captured metadata object after refilling buffers (`643–752`).

The target-verify update copies `spec_info.custom_mask` into the optional shared verify-mask buffer and computes mask indptrs; absence of a supplied custom mask produces `None` (`532–600`). Draft extend constructs a fixed-stride QO indptr and cached-prefix-only KV table, subtracting per-request extend lengths where available (`602–641`). `TritonMultiStepDraftBackend` parallels the FlashInfer multi-step structure, but it shares a graph split-count buffer across child backends and avoids the FlashInfer host indptr override (`2027–2200`).

## Direct API and ownership comparison

| Concern | FlashInfer owner and representation | Triton owner and representation |
|---|---|---|
| Qwen2 invocation | `RadixAttention` passes Q/K/V, layer geometry/scales, and `ForwardBatch`; wrapper APIs execute the kernel (`qwen2.py:192–213`; `flashinfer_backend.py:1311–1528`) | Same `RadixAttention` boundary; in-tree kernel functions receive expanded metadata (`triton_backend.py:1338–1535`, `1828–2024`) |
| Cached KV identity | `KVIndexTable` is gathered into `int32` FlashInfer indices and planned into NHD paged wrappers (`1711–1825`, `2132–2326`) | `KVIndexTable` is gathered into `int64` indices consumed directly by extend/decode kernels (`460–479`, `754–1018`) |
| Prefill split | Optional ragged current K/V plus paged cached prefix, merged by LSE; otherwise paged full sequence (`1395–1467`) | Ordinary two-stage extend kernel consumes current K/V and cached-prefix table; deterministic path builds unified indices (`1508–1535`, `1680–1826`) |
| Decode | Planned paged decode wrapper; page visibility is embedded in wrapper plan (`1472–1528`) | Decode kernel receives KV indptr/indices and split-result buffers explicitly (`1828–2024`) |
| Custom/tree mask | `spec_info.generate_attn_arg_prefill` supplies mask; wrapper plan receives it (`2204–2326`) | `spec_info.custom_mask` plus computed `mask_indptr`; extend/verify kernel receives both (`871–930`, `1462–1534`) |
| Sliding window | Separate wrappers and trimmed page tables; paged plan may receive `window_left`; ragged-prefix merge may use explicit uint8 mask (`1618–1669`, `1939–2074`) | Separate window indptr/indices/offsets selected by per-layer window flag (`1441–1453`, `2203–2255`) |
| Graph ownership | Wrappers bind address-stable buffers; planning refreshes them out of graph (`699–871`, `1051–1305`) | Metadata views bind address-stable buffers; table and write-loc refresh occurs out of graph (`643–752`, `1020–1291`) |

## External and unexpanded implementation boundaries

The external FlashInfer package implementation was unavailable in these repositories and was not read. Consequently, the internal behavior of `BatchDecodeWithPagedKVCacheWrapper`, both prefill wrapper classes, `fast_decode_plan`, their `plan/begin_forward/forward` methods, and cascade `merge_state` is represented only by the arguments and state used at SGLang call sites.

The imported in-tree Triton kernel bodies (`decode_attention_fwd`, `extend_attention_fwd`, `extend_attention_fwd_unified`, verify kernels, metadata split kernel, KV-index kernels, and DCP collectives), `ForwardBatch`, `SpecInput.generate_attn_arg_prefill`, `KVIndexTranslator`, and KV-pool implementations were outside this bounded read. Their internal mask arithmetic, page-address translation, physical storage layout, kernel launch grids, and collective implementation are not asserted beyond the explicit interfaces above.

No runtime trace, server arguments, resolved runtime context, GPU capability probe, or H100 execution record was part of this sector. Static support and factory reachability therefore do not identify the backend used by the target deployment.
