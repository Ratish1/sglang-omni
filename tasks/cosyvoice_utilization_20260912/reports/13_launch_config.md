# Sector 13 — launch and configuration mechanics

## Entry points and ownership

`python -m sglang_omni.cli` imports the Typer `app` and invokes it (`cli/__main__.py:1-4`). `cli/__init__.py:1-16` registers `config`, `check-gpu`, and `serve`; `serve` accepts unknown options and extra arguments so model/stage-specific dotted flags reach `ConfigManager`. `cli.serve.launch_server` is a lazy import of `serve.launcher.launch_server` (`cli/serve.py:32-35`).

The launch ownership chain is `serve` -> configuration-source construction -> `ConfigManager.merge_config`/`ConfigResolver.resolve` -> TP-derived gap filling -> `launch_server` -> `_run_server` -> `MultiProcessPipelineRunner.start` -> OpenAI app creation -> profiler-route mounting -> Uvicorn (`cli/serve.py:254-434`; `serve/launcher.py:375-473,514-560`).

Model-path-only resolution is owned by `resolve_config_cls_for_model_path` (`config/manager.py:22-54`). A non-directory `repo@revision` is split and the revision is passed to HF metadata lookup. Resolution tries `AutoConfig`, raw config, Mistral, NeMo, CosyVoice3-layout, and AuK-layout detectors in that order, then maps the architecture through `PIPELINE_CONFIG_REGISTRY`. The actual model class for CosyVoice is `FunCosyVoice3PipelineConfig`, exported as `EntryClass` (`models/fun_cosyvoice3/config.py:32-109`). Its factory import identities are string paths under `sglang_omni.models.fun_cosyvoice3`: `stages.create_preprocessing_executor`, `stages.create_sglang_tts_engine_executor`, and `stages.create_vocoder_executor` (`config.py:49-95`).

## Exact source precedence and conflict rules

Every source becomes `ConfigPatch(path,value,source,layer,specificity)` (`config/patch.py:95-170`). Cross-source layers are model default 0, YAML 10, CLI 20. Within a layer, specificity is broadcast 0, shared-role 10, explicit 20 (`patch.py:52-92`). Patch application order is ascending `(layer,specificity,path depth,insertion index)`, so stronger/deeper patches apply later (`210-225`). Two patches writing the same canonical path with equal rank and unequal values are rejected; equal values are accepted. Insertion order only breaks an already-accepted tie (`231-269`).

`serve` selects a baseline from the config file first, the text variant second, or the model-path default otherwise (`cli/serve.py:363-380`). With a config file and `--model-path`, model path becomes a CLI-layer explicit patch and outranks the file (`396-403`; `config/sources.py:169-186`). `--mem-fraction-static` expands into a CLI-layer broadcast patch for every engine stage (`cli/serve.py:111-149`). Dotted per-stage CLI patches have explicit specificity, so they outrank that broadcast. File `shared:` selectors expand at role specificity, while explicit `stages:` leaves use explicit specificity (`config/sources.py:189-242,305-356`).

Unknown Typer arguments are parsed as ordered key/value pairs, including `--key=value`; repeated keys survive for conflict detection, and a trailing key without a value fails (`config/manager.py:68-95`). Only the first dotted flag segment has hyphens normalized to underscores (`188-197`). CLI spelling implies `stages.` for a stage-name first segment; explicitly spelling `stages.` in a dotted CLI flag is refused, while canonical paths remain accepted by `config explain` (`config/compat.py:24-66`; `config/sources.py:113-166`). A whole typed group cannot be written as one dotted flag, except a freeform key. Text `none` maps to `None`; typed coercion rejects boolean-to-number and float-to-int loss, while untyped values parse true/false/none/int/float where possible (`config/path.py:359-425,792-817`).

`ConfigResolver.resolve` first rejects conflicts, deep-copies `base.model_dump()`, records baseline provenance, and applies patches in precedence order (`config/resolver.py:43-88`). Leaf/non-dict values replace; dicts at container paths recursively deep-merge (`96-116`). If `model_path` changes without an explicit `name`, and the dumped name equals the old model path, name is cleared so model validation can rederive it (`66-78`). The resolver rebuilds the concrete Pydantic config class and records its post-validation values for every touched path (`78-88`).

After source resolution, `apply_tensor_parallel_engine_overrides` derives engine settings from the resolved TP size/topology and writes only engine keys absent from `stage.engine.overrides()` (`cli/serve.py:189-251`). It writes through compiled `ConfigPath` into a dump and rebuilds the concrete config. For configured topology-gated stages, custom all-reduce is changed from disabled to enabled only when the GPU topology probe says disabling is unnecessary (`161-227`). This derivation is after patch resolution rather than another precedence layer. `config resolve` mirrors it and records derived provenance separately (`cli/config.py:116-202`).

## File input, paths, and resolved serialization

YAML parsing uses a SafeLoader subclass that refuses duplicate mapping keys (`config/sources.py:62-85`). A file must be a mapping and name `config_cls`; removed `stage_overrides`, `runtime_overrides`, and `entry_stage` blocks receive directed errors (`359-396`). The class is obtained by registered class name. A minimal baseline is constructed from class defaults plus only fields Pydantic reports missing and that the file supplies; every other top-level value becomes a patch exactly once (`397-432`). `stages:` must be a mapping keyed by declared stage names and cannot alter a stage name or topology. Nested bodies flatten to one patch per schema leaf (`305-356,479-497`). `shared:` selectors can choose named stages and/or all engine stages and then exclude names; empty/unknown/no-match selectors fail (`189-302`).

`ConfigPath.parse` compiles dotted paths against the Pydantic schema and switches to the model-declared stage subclass after `stages.<name>` (`config/path.py:232-286`). Stage collections are name-addressed and numeric indices are refused (`467-578`). User sources cannot write `config_cls`, the stages collection, entry stage, stage names/factory paths, routing, stream/fan-in wiring, or payload projection (`80-166,325-353`). Reads resolve named list items; writes can create missing dicts only along schema-allowed mapping paths and never create a missing stage (`427-459,701-748`).

`dump_user_config` is the canonical user serialization (`config/sources.py:456-476`). It calls `model_dump(mode="json")`, removes internal `entry_stage`, converts the internal stage list to a `stages` mapping keyed by name, removes `name` from each body, and drops `engine: null` on non-engine stages. `serve` prints this YAML only for `--colocate` or debug logging (`cli/serve.py:59-75,419-420`). `config view/export` serialize model defaults with the same function (`cli/config.py:42-91`); `config resolve --show config` serializes the fully resolved and TP-derived config, `--show diff` compares to the baseline, and `--show provenance`/`config explain` render recorded source history (`205-344`). `ProvenanceMap` stores ordered contributions, pre-patch baseline and post-validation resolved value per canonical path, marking the final winner and displaying validation rewrites (`config/provenance.py:41-146`).

## Fun-CosyVoice topology and launch defaults

The Fun-CosyVoice config declares three stages and one process-local edge (`models/fun_cosyvoice3/config.py:32-95`). All three stage records set `process="pipeline"`. Preprocessing has no GPU field, `max_concurrency=8`, and routes to `tts_engine`. The engine is GPU 0, BF16, ONNX intra-op threads 16, token hop 25, routes to vocoder, and streams to vocoder. The vocoder is GPU 0 and terminal, accepts streams before the complete payload, defaults BF16 Flow, 8000 admission frames, merge gap 384, padding budget 25%, batch size 16, wait 30 ms, TRT false, hop 25/max 100, and hop growth enabled. The declared local edge is preprocessing -> engine (`45-95`). Both compile and TensorRT flags true are rejected during config post-init (`17-29,97-106`).

The HTTP bind defaults are host `0.0.0.0`, port `8000`; model name defaults to pipeline name, log level to info, realtime off, and TTS batch cap to the protocol default (`cli/serve.py:282-342`; `serve/launcher.py:375-387,424-456`). CLI accepts and validates an allowed local-media directory, normalizes repeated/comma-separated domains to lowercase, and requires a positive TTS batch limit (`cli/serve.py:78-99,289-318,422-434`). If the requested port is occupied, `_find_available_port` normally binds an ephemeral free port and warns; `SGLANG_OMNI_STRICT_PORT=1` makes that a hard error (`serve/launcher.py:93-115`). Startup timeout comes from `SGLANG_OMNI_STARTUP_TIMEOUT`, default 600 seconds (`395-397`). Uvicorn uses keep-alive 120 seconds (`461-469`).

The launcher applies GPU compatibility environment defaults immediately before `asyncio.run` (`launcher.py:514-560`). Placement/process topology is resolved inside `MultiProcessPipelineRunner.start`; the launcher reads the fused plans back and logs process groups, TP process groups, stage GPU/memory budgets, per-GPU totals, and best-effort hardware name/memory (`127-201,395-419`). `utils/device.py:17-74` resolves omitted device type from the active platform and omitted accelerator index from that device module's current device; an explicitly indexed `device` string is rejected because placement supplies the index. CUDA TP processes with `tp_size>1` map a stage GPU through any preexisting `CUDA_VISIBLE_DEVICES`, expose only that mapped device, set one-visible-device and disable TP imbalance checking, and default `NCCL_NVLS_ENABLE=0` unless already supplied (`platforms/cuda.py:53-99`). Fun-CosyVoice's default TP size is inherited/default and no H100-specific branch exists in its config or launcher path.

## Profiler HTTP routes

`serve.launcher` owns and unconditionally mounts four root POST routes after app creation: `/start_profile`, `/start_request_profile`, `/stop_profile`, and `/stop_request_profile` (`launcher.py:239-372,457-460`). `StartReq` accepts optional run ID, trace template, torch-profiler config, event directory, and `enable_torch` default true; request-only start accepts run ID/event directory (`239-254`). Default run IDs use wall-clock `run_YYYYMMDD_HHMMSS`; default paths are `<SGLANG_TORCH_PROFILER_DIR>/<run>/trace` and `.../events` (`118-123,256-257`).

`/start_profile` requires a trace template when torch profiling is enabled and no profiler env directory exists. With torch disabled, it requires an event directory under the same condition (`265-293`). It attempts to start the coordinator event recorder, logs and continues on recorder error, then broadcasts start parameters to every stage control endpoint (`294-316`). `/start_request_profile` uses an empty trace template and `enable_torch=False`, starts the coordinator recorder, and broadcasts the request-event configuration (`318-348`). Both stop routes optionally match/stop the coordinator's active run and broadcast a stop; `run_id=None` acts as a wildcard (`350-370`). `ProfilerControlClient` and stage-side control endpoint behavior are external owners not read in this sector, so stage acknowledgment/error aggregation and on-disk event/trace details remain unresolved here.

## Cookbook/config comparison

The cookbook's launch flags are valid dotted paths under the current surface: Flow admission (`docs/cookbook/fun_cosyvoice3.md:216-221`), compile (`235-240`), and TensorRT (`255-260`). Its stated factory defaults match the model config for preprocessing concurrency 8, ONNX threads 16, Flow batch 16/wait 30, BF16 Flow, FP32 HiFT supplied by the factory default, and compile off/TRT off (`227-233`; model config `49-95`). The source default contains no explicit `enable_dit_torch_compile`, and post-init reads absent extras as false (`config.py:97-106`).

The cookbook contains duplicated request/streaming sections (`51-199` and `286-425`). The first generation table states `repetition_penalty=1.1` (`193-197`), while the later table states `1.21` (`419-423`); the inspected request builder default is 1.21. The cookbook says first startup can take several minutes while `tts_engine` captures CUDA graphs (`42`), while its later compile section separately describes DiT `torch.compile` as off by default (`231-239`); these refer to separate engine CUDA graph and vocoder DiT compile paths. No cookbook YAML file is supplied for Fun-CosyVoice; examples use `--model-path` and optional dotted flags, so resolved output must come from `config resolve` or debug/colocate merged-config printing rather than an example config file.
