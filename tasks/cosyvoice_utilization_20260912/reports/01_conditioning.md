# Sector 01 — conditioning mechanics

## Scope and ownership

This report describes inspected mechanics only. The reachable Fun-CosyVoice3 conditioning path is:

`create_preprocessing_executor` -> `SimpleScheduler(max_concurrency=8 by default)` -> `preprocess_cosyvoice3_payload` -> optional `ReferenceEncodeService.get_or_encode` -> `_CosyVoice3ReferenceEncodeHook.encode_one` -> serialized `_prepare_cosyvoice3_request` -> process-local prepared-request publication -> AR `build_sglang_cosyvoice3_request` -> `Req` plus `CosyVoice3SGLangRequestData` -> `FunCosyVoice3ModelRunner._build_prefill_input_embeds`.

The preprocessing executor is constructed at `sglang_omni/models/fun_cosyvoice3/stages.py:777-790`. `FunCosyVoice3EngineBuilder.setup_model` creates the tokenizer and two ONNX encoders and registers the process-local context at `engine_builder.py:79-124`; its AR adapters and abort callback are supplied at `engine_builder.py:136-140`. The generic text/resource-connector helpers, shared `PreparedRequestQueue`, and global `SpeakerArtifactCache` are not imported by the Fun-CosyVoice3 request builder. The reachable audio loader is `sglang_omni/utils/audio.py:270-344`; it imports only the WAV parser from `preprocessing/audio.py` on its fast path (`utils/audio.py:181-209`).

## Request and text preparation

`FunCosyVoice3State` is the per-request pipeline state (`payload_types.py:13-31`). `sample_rate`, `text`, `language`, `stream`, `speed`, `generation_kwargs`, and the three Flow tensors/audio results have declarative wire codecs. `instructions`, `ref_audio`, `ref_text`, and `seed` are ordinary fields. The Flow fields use `tensor_list`, so `to_dict` detaches tensors, copies them to CPU, and converts them to nested lists (`pipeline_state.py:65-72,100-120,215-244`). Usage fields come from the base state and are emitted only when nonzero (`pipeline_state.py:28-62,294-304`).

`build_cosyvoice3_state` (`request_builders.py:436-485`) reads `payload.request.inputs`, `.params`, and `.metadata`; non-dict `tts_params` becomes `{}`. `_normalize_cosyvoice3_inputs` (`488-510`) accepts a text string, stringifies another non-dict value, or reads a dict. Structured `references` must be a list containing at most one dict. Reference-audio precedence is flat `inputs.ref_audio/audio/file`, then the first reference's `audio_path/ref_audio/audio`, then an audio data URI derived from that reference, then `tts_params.ref_audio` (`444-455`). Reference-text precedence is flat input, reference text, then `tts_params.ref_text` (`456`).

`normalize_language` (`513-516`) maps `None`/empty string to `"auto"`; `resolve_optional_text` (`532-536`) stringifies and strips optional text. Instructions are chosen from `tts_params.instructions/instruct` then request params; simultaneous nonempty instructions and reference text raise (`459-469`). Stream, speed, and seed are resolved from TTS params over general params (`470-473`). `_normalize_cosyvoice3_seed` rejects booleans and fractional floats, converts with `int`, then masks into `SAMPLING_SEED_MASK` (`519-529`).

`_build_cosyvoice3_prompt_text` (`539-553`) produces one of three prefixes. Instructions already containing `<|endofprompt|>` are used directly; otherwise they are prefixed with `"You are a helpful assistant. "` and suffixed with the marker. Reference text already containing the marker is used directly; otherwise it follows `"You are a helpful assistant.<|endofprompt|>"`. With neither field, that last prefix alone is returned. In `_prepare_cosyvoice3_request`, target text is tokenized first and its token count captured before this prefix is tokenized, prepended, and concatenated (`626-645`). `CosyVoice3Tokenizer.__call__` returns CPU `int32` shape `[1,T]`; preparation moves it to the model parameter device before calling `model.text_embed_tokens` under `no_grad` (`utils.py:13-39`; `request_builders.py:633-645`). The tokenizer constructor loads `AutoTokenizer`, adds EOS/PAD and the full special-token list, and defaults decoding to skip special tokens (`utils.py:13-40,222-505`).

`build_generation_kwargs` (`request_builders.py:578-614`) recognizes six fields. Values equal to enumerated implicit defaults are omitted unless named in `tts_params.explicit_generation_params`; explicitly present `max_new_tokens` is always converted to int and retained. The later AR builder derives the default generation bounds from the target-only text token count: `max=min(2048,20*max(target_count,1))`, unless explicitly supplied, and `min_new_tokens=min(2*target_count,max_new_tokens)` (`742-789`). It creates `SamplingParams`, normalizes with the null tokenizer whose EOS is the model EOS, verifies against `TOTAL_VOCAB_SIZE`, and registers all `CONTROL_TOKEN_IDS` as stop tokens (`73-95,759-789`).

## Reference audio, ONNX sessions, and tensor contracts

`FunCosyVoice3EngineBuilder.__init__` validates the stream token hop and clamps the configured ONNX intra-op count to `[1, os.cpu_count()]` (`engine_builder.py:31-48`). `setup_model` creates one `SpeechTokenizerV3` session and one `SpeakerEncoder` session, passing the same clamped intra-op count to each (`102-116`). Each constructor creates a distinct ORT `SessionOptions`, enables all graph optimizations, and sets `intra_op_num_threads` (`utils.py:42-64,97-116`). No inter-op setting is made in these classes. The speech tokenizer requests providers `[CUDAExecutionProvider, CPUExecutionProvider]` when `device.startswith("cuda")`, otherwise CPU only (`57-64`). The CAMPPlus speaker encoder always requests only `CPUExecutionProvider`, although it stores the supplied device string (`112-117`). Thus reachable CUDA engine setup allows speech-tokenizer ONNX CUDA with CPU fallback, while CAMPPlus stays on ORT CPU.

`_CosyVoice3ReferenceEncodeHook` identifies itself as model `fun_cosyvoice3`, encoder `speech_tokenizer_v3+campplus+matcha_mel`, artifact `reference_conditioning` (`request_builders.py:218-228`). Construction records the provided checkpoint root/model identity and hashes a JSON config containing 16/24 kHz rates, exact mel parameters, and the two-frames-per-token alignment contract (`230-253`). `bind_encoders` attaches the process-local sessions; encoding before binding raises (`255-281`).

`encode_one` loads the same source independently at 16 kHz and 24 kHz (`277-300`). `_load_prompt_audio` and `_load_prompt_audio_24k` delegate to the shared synchronous loader with mono defaults (`419-433`). The loader accepts byte-like objects, data URIs, HTTP(S), file URLs, and filesystem strings; HTTP uses a direct `httpx.get` with `REQUEST_TIMEOUT` default 5 seconds and follows redirects (`utils/audio.py:258-317`). It decodes via a direct PCM WAV fast path where applicable, otherwise TorchCodec-backed torchaudio with SoundFile fallback when TorchCodec cannot load (`36-156,181-209,301-312`). It averages channels, converts float32, resamples through platform-selected torchaudio or SciPy, squeezes mono, and returns CPU NumPy (`318-344`). Because 16 kHz and 24 kHz are separate calls, an uncacheable HTTP reference causes two independent HTTP loads in one `encode_one` invocation.

`SpeechTokenizerV3.extract_speech_token` requires 16 kHz, reshapes 1-D audio to `[1,S]`, rejects duration over 30 seconds, computes Whisper 128-bin log-mel features in PyTorch, passes CPU NumPy feature and int32 feature length to ORT, and returns CPU `int32` shape `[1,N]` (`utils.py:67-94`). `SpeakerEncoder.extract_embedding` reshapes 1-D audio, computes CPU Kaldi fbank with 80 bins/no dither/request sample rate, mean-centers across frames, calls its CPU ORT session with `[1,frames,80]`, and returns a CPU torch tensor shaped `[1,flattened_output]` (`119-137`).

`extract_prompt_speech_feat` requires 24 kHz and input shape `[samples]` or `[channels,samples]`, converts to float32 NumPy then CPU torch, calls Matcha mel with FFT/window 1920, hop 480, 80 bins, no centering, validates `[batch,80,frames]`, then returns contiguous `[batch,frames,80]` (`utils.py:140-187`). `_align_flow_prompt` requires speech tokens `[1,N]` and mel `[1,F,80]`; it chooses `min(N,floor(F/2))`, and returns contiguous token and mel prefixes of lengths `n` and `2n` (`request_builders.py:556-575`). The artifact keeps untrimmed speech tokens for the LLM, aligned tokens/features for Flow, and the speaker embedding (`283-300`).

Without reference audio, preparation creates CPU zeros with shapes/dtypes: speaker `[0,192]` default float, LLM/Flow speech tokens `[1,0]` int32, and Flow features `[1,0,80]` default float (`647-658`). With a reference, all four tensors arrive as fresh CPU clones from the reference cache. LLM prompt speech is included only when `ref_text` is non-None; instruction and cross-lingual modes use an empty speech-token tensor for the LLM while retaining Flow conditioning (`660-668`).

`build_llm_prompt_embeddings` explicitly discards the CAMPPlus embedding. It computes SOS and task embeddings on the model device, moves nonempty prompt speech tokens to that device for `speech_embed`, creates an empty `[1,0,H]` tensor on the model device/dtype otherwise, and concatenates `[SOS,text,task,prompt_speech]` along sequence (`utils.py:190-219`). Final preparation squeezes batch dimension, detaches, and enforces model device/dtype (`request_builders.py:670-686`). `build_embedding_cache_key_ids` copies the entire embedding matrix to CPU float32 and hashes each row with 8-byte BLAKE2b, masking to positive 63 bits (`617-623`). It then constructs the corresponding CPU `long` tensor (`687-700`). This CPU copy is the explicit synchronization/copy boundary used to derive pseudo token IDs from GPU prompt embeddings.

## Cache identity, lifetime, coalescing, and locks

`_cosyvoice3_reference_input_key` (`request_builders.py:111-151`) keys data URIs and byte-like values by xxh3 content hash. Dicts first recurse through `audio_path/path`, then through a derived data URI. NumPy inputs include dtype, shape, and contiguous bytes; torch inputs detach, copy to CPU contiguous storage, and include dtype/shape/bytes. HTTP(S), unsupported file URL authorities, invalid data URIs, unsupported objects, and unresolved paths return no key. Local and accepted file URLs use `reference_path_cache_key`.

`reference_path_cache_key` (`preprocessing/cache_key.py:55-160`) resolves and stats an existing file, memoizes up to 1024 entries by resolved path, size, mtime-ns, and ctime-ns, and normally validates memo hits with an xxh3 sentinel over head/middle/tail samples plus size. A miss reads and hashes full file content. It stores only if a second stat-derived key is unchanged. CosyVoice uses default `trust_stat=False`, and `KeyedReferenceEncodeHook.revalidate` recomputes both input and option keys after encoding (`reference_encoder.py:64-100`), so a changed file is not inserted under the pre-encode key. The fixed options key is `prompt_16k+flow_24k+mono` (`request_builders.py:270-275`). `ReferenceEncodeKey.to_string` serializes model ID, model revision, encoder ID/config hash, artifact kind, input key, and options key as sorted compact JSON (`reference_encoder.py:24-35`).

The registered service is process-local, bounded to 256 entries and 128 MiB, with a 130-second follower/batch wait timeout (`request_builders.py:348-379`). The Hook does not override `can_encode_batch`, so `ReferenceEncodeService` computes `_batching=False`; no internal batch queue/thread is created for this path (`reference_encoder.py:57-61,168-185`). Encoding runs in the invoking SimpleScheduler worker thread. Up to eight preprocessing workers can therefore enter reference lookup/encoding concurrently; prompt finalization is separately serialized (`stages.py:777-790`; `request_builders.py:718-724`).

`ReferenceEncodeService.get_or_encode` (`reference_encoder.py:304-373`) normalizes input and handles uncacheable inputs directly while incrementing `uncacheable` and failures under its lock. For cacheable keys, one service mutex protects cache lookup, inflight-map transitions, and counters. A hit returns `hook.load_artifact`. A same-key follower obtains the leader future, waits up to 130 seconds, and loads the stored value. A leader encodes outside the mutex, converts to storage form, revalidates, then under the mutex optionally inserts and always removes the inflight entry. Exceptions remove the inflight entry, increment `failed`, complete the future exceptionally, and re-raise. Success completes the future after releasing the lock. Follower failures are re-raised as fresh exceptions; optional description text is attached as an exception note (`118-127,338-370,390-396`).

The hook's `store_artifact` produces a tagged dict and clones every tensor to detached CPU storage; `load_artifact` validates tag and all four fields and clones all fields again (`request_builders.py:302-330`). Consequently cached storage does not alias either encoder outputs or returned per-request tensors. `StageOutputCache` itself is an access-ordered LRU. `put` measures tensor payload bytes, detaches recursively, replaces existing keys, rejects a single oversize entry, and evicts oldest entries against item and byte bounds (`stage_cache.py:59-68,71-132,173-184`). This service does not configure `cache_device` or pinned memory, and its hook already stores CPU clones. Cache get/put has its own non-reentrant lock (`102-132`).

The service exposes hit, miss, merged, entry, byte, eviction, failure, uncacheable, batch, and batched-item counts (`reference_encoder.py:375-388`) and logs the same at INFO at most once per 60 seconds after successful leader/hit operations when a log prefix exists (`398-420`). Failures in an unused batch worker would be logged; no such worker is enabled for this hook. Context replacement and `clear_cosyvoice3_preprocessing_context` replace/drop the service and clear prepared requests but do not call `ReferenceEncodeService.close` (`request_builders.py:348-388`). No explicit cache TTL exists; lifetime is the registered service object's process lifetime, context replacement, or reachability/garbage collection, subject to LRU limits.

`SpeakerArtifactCache` (`speaker_cache.py:19-129`) is a distinct process-global 512 MiB cache keyed by model type, case-preserved voice name, integer voice version, and artifact kind. It uses an outer `RLock` plus `StageOutputCache`, tracks hits/misses/evictions/delete invalidations, and can clear entries case-insensitively by voice. Fun-CosyVoice3 conditioning does not call it. `PreparedRequestQueue` (`prepared_request_queue.py:20-111`) is likewise unused by this model; its generic contract atomically tracks context, prepared dict, inflight IDs, and abort tombstones, accepting publish only for a live non-aborted inflight ID.

## Prepared-request publication, cancellation, and AR handoff

The actual Fun-CosyVoice3 handoff is `_PREPARED_REQUESTS`, guarded by `_PREPARED_REQUESTS_LOCK`; `_PREPROCESSING_FINALIZE_LOCK` is a separate mutex (`request_builders.py:342-345`). Context registration holds the prepared lock while replacing context and clearing all prepared entries (`348-380`). Clear does the same while setting context to `None` (`383-388`). Cleanup removes one stringified request ID idempotently (`390-392`).

`preprocess_cosyvoice3_payload` snapshots the context under the prepared lock, builds state, performs reference get/encode without the finalization lock, then holds the finalization lock across target/prompt tokenization, model embedding calls, row hashing, and prepared-object construction (`704-724`). It attaches Flow tensors to state; `state.to_dict` copies them into nested CPU lists. The returned `StagePayload.data` contains those serialized fields plus a marker equal to `payload.request_id` (`726-736`). Only afterward does it acquire the prepared lock and publish the heavyweight prepared object by request ID (`737-739`).

The preprocessing `SimpleScheduler` runs this synchronous function via `asyncio.to_thread` when concurrency exceeds one (`simple_scheduler.py:257-305`). `abort` records the ID and immediately calls the cleanup callback (`320-327`). Workers check the abort set before compute, after compute, and on exception; consuming an abort removes the tombstone and calls cleanup again (`77-91,277-300`). Thus abort does not interrupt reference encoding or model finalization already executing. If abort occurs during preprocessing, the immediate callback may find no published entry; after compute returns, the worker consumes the tombstone and removes any entry that preprocessing published, and it emits no result. The aborted-ID set is pruned from more than 10,000 to 5,000 entries by set iteration (`320-326`).

`pop_prepared_cosyvoice3_request` reads the marker, atomically removes its entry, and raises if a marked payload has no entry (`request_builders.py:395-416`). `build_sglang_cosyvoice3_request` requires that pop to succeed; it consumes the prepared object before later SamplingParams/Req construction (`742-752`). The created upstream `Req` has the pseudo IDs as `origin_input_ids`, an empty origin text, model vocabulary size, normalized sampling params, the null tokenizer, `_input_embeds_are_projected=True`, and `_codec_suppress_tokens=None` (`791-800`). The actual embedding tensor is not assigned to upstream `Req.input_embeds`; it is retained in `CosyVoice3SGLangRequestData.prompt_input_embeds`, along with the CPU pseudo-ID tensor and Flow tensors (`802-817`). The data flag `input_embeds_are_projected` is also set true.

OmniScheduler's request builder may run in a request-build executor; it emits start/end events around the builder (`omni_scheduler.py:900-967`). Admission normalizes upstream token containers, sets `req._omni_data=req_data`, and appends the Req to its waiting queue under its admission lock (`1190-1253`). At batch execution it wraps each Req into `SchedulerRequest(data=req._omni_data)` (`1456-1465`). `FunCosyVoice3ModelRunner._build_prefill_input_embeds` uses each upstream Req's `extend_range.length` and `prefix_indices` length to slice the corresponding rows from `data.prompt_input_embeds`; it concatenates rows and copies/casts to the forward batch input-ID device and model dtype (`model_runner.py:185-205`). `_forward_with_input_embeds` performs another device/dtype `.to`, initializes attention metadata, and calls the model with both input IDs and the projected input embeddings (`207-233`). Prefix matching therefore indexes prompt embedding rows by the hash-derived pseudo IDs while model execution consumes the stored projected rows.

On AR abort, OmniScheduler records the ID, marks a running Req with `FINISH_ABORT` or immediately finishes non-running matches, removes/cancels pending request-build/admission records, drops waiting requests and detaches their `Req -> data` link, invokes the model abort callback immediately unless cleanup is deferred for a running request, and drains inbox records (`omni_scheduler.py:1817-1878,2285-2341`). Cancellation of a running request-build future does not interrupt Python work that has already started; its result is discarded when the completed future is drained for an aborted ID (`1086-1117`). For a running abort, terminal handling later invokes the callback, emits aborted path status, and detaches `req._omni_data` (`1635-1673`). Normal terminal cleanup clears the generic `prefill_input_embeds` and `decode_input_embeds` fields, then detaches through `_close_completed_request`; the model-specific `prompt_input_embeds` field is not explicitly nulled in the inspected terminal block (`1699-1723`). The Req/data cycle is broken by `_detach_request_data` (`98-100`).

## Other assigned module mechanics

`StageOutputCache` symbols are `_CacheEntry` (`stage_cache.py:16-20`), `_to_pinned_host` (`22-27`), recursive `_detach_value` (`30-56`), `_value_size_bytes` (`59-68`), and `StageOutputCache` (`71-184`). Pinned host allocation is attempted only when configured for CPU and CUDA is available; a runtime failure logs a warning and uses pageable storage (`22-45,88-99`). `remove_if_same` removes only identical object storage; `remove_if` snapshots keys and evaluates caller predicates outside the cache lock (`139-167`).

`ReferenceEncodeHook` defines normalization/key/encode/store/load/revalidate/batch extension points (`reference_encoder.py:38-61`); `KeyedReferenceEncodeHook` builds structured keys (`64-100`); `TensorReferenceEncodeHook` stores detached CPU copies and loads copied dtype-adjusted tensors (`103-115`). `ReferenceEncodeService.close` sends a batch sentinel, joins for at most five seconds, and calls an optional hook close (`195-203`). Its generic batch worker drains leaders up to count/deadline, fans out fresh exceptions, fails queued waiters on shutdown, and falls back from a failed batch encode to individual encodes (`212-302`); this machinery is unreachable for the CosyVoice hook because batching is disabled.

`preprocessing/audio.py` owns PyAV byte decode (`19-52`), direct PCM/IEEE WAV parsing (`55-124`), linear NumPy resampling (`127-136`), file loading (`139-146`), `AudioMediaIO` (`149-189`), async normalization/fetch (`192-250`), HF audio tensor extraction (`253-267`), and generic media cache key delegation (`270-278`). Apart from `_parse_wav_bytes` through the shared loader's fast path, these APIs are not called by the inspected CosyVoice path.

`preprocessing/cache_key.py` additionally provides generic sampled file hashes and media hashes (`29-52,163-235`). Those generic paths hash URL strings and sampled files; CosyVoice instead calls `reference_path_cache_key`/`hash_bytes` directly.

`ResourceHTTPConnection` lazily owns sync/async httpx clients and close (`resource_connector.py:31-64`). `MultiModalResourceConnector` validates local roots, domain policy and optionally resolved-address categories; manually follows up to five redirects while validating every hop; caps declared and streamed bytes; and offloads async decode to an eight-thread global pool (`67-196,199-483`). Image/video fetchers and the lazy global connector occupy `485-566`. None is on the inspected CosyVoice reference path, whose shared loader calls `httpx.get` directly.

`preprocessing/text.py` loads optional HF chat templates, fills a tokenizer template from local/fallback models, normalizes role/content dicts, appends modality placeholders to the final message, and calls `tokenizer.apply_chat_template` with a generation prompt (`12-104`). None is called by CosyVoice; its text path uses `CosyVoice3Tokenizer` directly.

`typed_tensor.encode_typed_tensor` transports floating tensors as CPU float32 and integer tensors as uint16 when range permits, otherwise int32; it stores bytes/shape/dtype (`typed_tensor.py:21-52`). Decode honors an optional legacy object/list first, copies floats away from the read-only buffer, and restores integers as int64 (`55-78`). FunCosyVoice3State uses `tensor_list`, not `typed_tensor`, for conditioning and audio fields.

## Observability and unresolved runtime/external boundaries

Observed instrumentation consists of ReferenceEncodeService's counters and periodic INFO aggregate (`reference_encoder.py:375-420`), preprocessing/request-builder scheduler events (`omni_scheduler.py:954-967`), request model-path events and terminal status (`omni_scheduler.py:1635-1737,1817-1878`), large-download/decode DEBUG timings in the generic resource connector that CosyVoice does not use (`resource_connector.py:357-383`), and model/weight/session setup INFO logs (`engine_builder.py:96-100`). No per-reference audio load, ONNX-call, mel extraction, prompt-finalization, CPU-to-GPU copy, or row-hash timing/counter exists in the inspected CosyVoice files.

The exact runtime ORT provider actually selected, provider fallback events, effective ORT thread-pool implementation/affinity, external `whisper`, Matcha, torchaudio/Kaldi, TorchCodec/SoundFile, and checkpoint graph behavior require installed-library/runtime evidence. `Req`, `SamplingParams`, prefix matching, and extend ranges are owned by the separate SGLang repository; the inspected baseline shows Req construction/state and SamplingParams normalize/verify, but the full scheduler module and cache algorithms were outside this sector's complete-file coverage. No byte-for-byte numerical equivalence is asserted. No tests or model runs were executed.
