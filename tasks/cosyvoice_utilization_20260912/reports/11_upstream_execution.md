# Sector 11: upstream SGLang execution, graphs, sampling, and kernels

## Scope and baseline

This report is factual code archaeology for Omni commit `645b472cdb2d7b93a1825a5bfa6a603b62b03936`, SGLang commit `0bcd822377da7b5718e674eaf9c870d349424dd1` (`v0.5.19`), and the FlashInfer commit that its AOT build pins, `bc29697ba20b7e6bdb728ded98f04788e16ee021`. The latter was fetched from the official `https://github.com/flashinfer-ai/flashinfer.git` remote into `/private/tmp/cosyvoice-utilization-sources-20260912/flashinfer`; the detached checkout resolved to that exact commit. It does not establish the live GPU model configuration, resolved attention backend, tensor shapes, or timing. Those require runtime evidence. The assigned upstream files were read completely. Direct owners were followed through graph storage/replay, sampling metadata, attention selection, Qwen projection/norm/activation dispatch, and the in-tree JIT/AOT kernels. Explicit partial boundaries are listed at the end.

## Reached call graph and ownership

The synchronous CosyVoice path is:

`Omni ModelRunner.execute` -> `ForwardBatch.init_new` -> `FunCosyVoice3ModelRunner._prepare_and_forward` -> either:

* prefill: `custom_prefill_forward` -> `_build_prefill_input_embeds` -> `_forward_with_input_embeds` -> selected attention backend metadata init -> `FunCosyVoice3SGLangModel.forward`; or
* decode: upstream `tp_worker.forward_batch_generation` -> `sglang.srt.model_executor.ModelRunner.forward` -> `_forward_raw` -> decode CUDA graph replay when admitted, otherwise `EagerRunner.execute` -> `FunCosyVoice3SGLangModel.forward`.

Both branches then run `_sample_next_token_ids` because CosyVoice returns `True` from both sample-before-post hooks. That delegates to upstream `ModelRunner.sample` -> `SamplingBatchInfo` bias/grammar/penalty application -> `Sampler.forward`. CosyVoice then executes `_collect_tokens`, whose single batched `token_ids.tolist()` materializes the device result on the host, filters control-token IDs, stores CPU `torch.long[1]` code tensors, and may enqueue a vocoder chunk (Omni `model_runner/base.py:297-333,481-546,832-875`; CosyVoice `model_runner.py:48-116`).

The model itself deliberately bypasses Qwen2's standard `LogitsProcessor` and vocabulary-parallel LM head. It inherits and invokes `Qwen2Model`, but replaces input/output endpoints with `speech_embedding` and a plain `nn.Linear(hidden_size, 6761, bias=False)`. Decode embeds `input_ids`; prefill consumes supplied embeddings. Extend output is reduced to one final hidden row per sequence using cumulative `extend_seq_lens`; decode keeps one row per request. It returns `LogitsProcessorOutput(next_token_logits, hidden_states)` directly (Omni `sglang_model.py:26-91`). Therefore upstream `layers/logits_processor.py` describes the general SGLang contract and graph-buffer conventions, but its `LogitsProcessor.forward` and LM-head collectives are not called by this model's override.

Prefill slices each request's prompt tensor by cached-prefix length and current extend length, concatenates rows, transfers/casts to the model input device/dtype, plans attention metadata, enters the backend forward context, and explicitly reports `can_run_cuda_graph=False`.

The builder supplies `max_running_requests=32`, legacy `cuda_graph_max_bs=32`, decode graphs enabled, overlap scheduling disabled, torch compile disabled, `max_prefill_tokens=4096`, and `sampling_backend="pytorch"`; user/stage overrides can still alter resolved settings before publication (`engine_builder.py:60-77`). It does not name an attention backend.

## Qwen2 execution mechanics

`Qwen2MLP` (`qwen2.py:63-124`) owns packed gate/up projection, SiLU-and-multiply, and row-parallel down projection. `Qwen2Attention` (`126-235`) resolves TP-local query/KV head counts, packs Q/K/V into one biased column-parallel projection, applies RoPE, calls `RadixAttention`, and runs a row-parallel output projection. KV heads are partitioned when their total is at least TP size and replicated otherwise. `Qwen2DecoderLayer` (`237-313`) uses pre-norm residual flow: the first layer seeds the residual without addition; subsequent norms fuse/add the prior branch into residual; attention and MLP each receive normalized states. `Qwen2Model` (`315-470`) owns embeddings, PP layer partition, final RMSNorm, layer iteration, and optional auxiliary hidden capture. `Qwen2ForCausalLM` (`472-769`) owns the normal LM head/logits processor/pooler and load paths; CosyVoice reaches construction/loading but overrides the normal forward head.

The actual Qwen attention call is backend-owned. `RadixAttention.forward` reshapes K/V to `[tokens, local_kv_heads, head_dim]` and normally dispatches `get_attn_backend().forward(q,k,v,layer,forward_batch,save_kv_cache)` (`radix_attention.py:98-298`). Piecewise prefill can instead use registered custom ops with caller-owned output, narrow work to `num_token_non_padded_cpu`, temporarily narrow cache locations/positions, and zero graph-padding tails (`301-657`). That piecewise branch is unrelated to CosyVoice custom prefill because it directly calls the model under the ordinary attention context and declares graph use false.

Unquantized Q/K/V, output, gate/up, and down projections are `ColumnParallelLinear`/`QKVParallelLinear`/`MergedColumnParallelLinear`/`RowParallelLinear`. Column-parallel output stays sharded unless `gather_output`; row-parallel input is already sharded by default and its result is TP all-reduced unless a skip/fusion condition applies (`linear.py:311-522,524-951,953-1422,1424-1707`). Every projection calls its quantization method's `apply`; `UnquantizedLinearMethod.apply` uses packed AMX on an eligible CPU layer, AITER `tgemm` on enabled HIP, or the BF16 dispatcher when its CUDA/dtype/no-grad conditions hold, and otherwise `F.linear` (`quantization/unquant.py:335-436`). The BF16 dispatcher may choose a shape-tuned FlashInfer PR4266 direct/Split-K path, Hopper GEMV, or CuteDSL; its terminal fallback is `F.linear` (`90-334`). The remainder of `unquant.py` owns unquantized fused-MoE allocation, optional weight transforms, backend selection, and execution; Qwen2 dense MLP does not instantiate that MoE method.

## Attention backend authority

The effective pair belongs first to the published runtime config and then to the runner. `runtime_context.attention_backends()` derives `(prefill, decode)` from the published `get_exec().kernel` leaves, applying split-field fallback to the common backend (`runtime_context.py:1964-1976`, partial file read). `ModelRunner.init_attention_backends` resolves once and stamps `prefill_attention_backend_str` and `decode_attention_backend_str` on that runner before constructing backends (`model_runner.py:993-1020`). A draft worker's explicit `draft_attention_backend` overrides both modes for that runner. Otherwise `resolve_attention_backend_strs` uses the published pair. Different prefill/decode strings create a `HybridAttnBackend`; a common string creates one registered backend; TBO and PDMux add wrappers/groups (`attention_backend_setup.py:28-257`). Backend names and lazy factory imports are registered in `ATTENTION_BACKENDS`; model-specific wrappers can then compose full attention with sparse, short-convolution, Mamba, GDN, KDA, or Lightning backends (`attention_registry.py:1-542`).

No CosyVoice source names a backend, and the repository code alone cannot prove which default/override or device-specific factory was effective in the measured run. It can prove that both custom prefill and normal decode use the runner's constructed backend, and that decode graph capture initializes CUDA-graph state on that backend.

## Forward batches, padding, and streams

`ForwardMode` (`forward_batch_info.py:104-203`) defines extend, decode, mixed, idle, target-verify, draft-extend, prebuilt, split-prefill, and dLLM modes. Plain CosyVoice uses extend and decode. `ForwardBatch` fields span `394-619`; metadata readiness methods `621-683`; `init_new` `686-963`; position/MM helpers `965-1277`; DP padding `1279-1634`; TP scatter and post-forward unpadding `1636-1724`; helper views/position functions `1726-1863`.

`ForwardBatch.init_new` borrows scheduled GPU tensors and host metadata, transfers parameter vectors with pinned/nonblocking H2D where available, derives decode positions as clamped `seq_lens-1`, and derives packed extend positions/start offsets. It starts with attention metadata unplanned. CosyVoice custom prefill initializes the backend directly. The standard eager path prepares DP/TP padding before backend/model execution; decode graph replay instead loads static buffers and returns early (`model_runner.py:1481-1809`).

DP padding aligns token counts for attention TP/CP and chooses SUM_LEN or MAX_LEN based on collective/graph requirements. `_pad_inputs_to_size` pads input IDs, embeddings, request indices, sequence lengths, cache locations, positions, optional MRoPE and auxiliary tensors, using the attention backend's graph sequence-length sentinel. `post_forward_mlp_sync_batch` restores original mode/batch and slices dummy logits/hidden rows (`forward_batch_info.py:1294-1724`). These branches only matter when the corresponding distributed modes are enabled; their effective use for CosyVoice is not known from static source.

The upstream runner creates a dedicated `forward_stream` during initialization (`model_runner.py:401-407`). Omni's execution bridge selects the execution context/stream around each forward. Decode graph capture uses the process-wide graph-capture stream or PDMux stream groups. The process-wide pool owner creates one named capture stream and one graph memory-pool handle, shared because prefill and decode captures/replays are serialized; its optional borrow scope excludes concurrent graph users and synchronizes before retiring a borrow pool (`runner_utils/pool.py:1-230`). Replay first enqueues live-to-static buffer copies and attention metadata preparation, then invokes the captured graph. Shared-read completion is published as a device event at the backend-declared pre-, in-, or post-replay point (`decode_cuda_graph_runner.py:495-537,1276-1515`).

## Decode CUDA graphs

Graph configuration is a per-phase `CudaGraphConfig`: decode defaults to `full`; prefill defaults to breakable on CUDA and tc-piecewise elsewhere. Each phase owns backend, max/bucket sizes, and compile controls (`cuda_graph_config.py:16-282`). CosyVoice's builder enables graphs and caps legacy decode size at 32; the resolved config bag is authoritative.

`BaseCudaGraphRunner` owns GC freezing, bucket construction/alignment, and nearest-ceiling bucket selection (`base_cuda_graph_runner.py:46-159`). Capture sizes come from resolved decode `bs`, are aligned so `bs * captured_req_width` satisfies graph alignment, are capped to request-pool capacity, and are split into optional torch-compile buckets. Plain non-speculative CosyVoice has `captured_req_width=1` (`model_runner.py:796-817`; `decode_cuda_graph_runner.py:209-494`).

`DecodeCudaGraphRunner.__init__` (`217-494`) fixes capture mode/width, derives buckets, initializes backend CUDA graph state, allocates pointer-stable buffers, shares them through the pool/registry, and captures immediately. For plain CosyVoice it captures DECODE, one token per request; no speculative/ragged branch is reached. Its `can_run_graph` (`676-781`) rejects dynamic replacement embeddings, incompatible speculative widths/layouts, unsupported padded/exact sizes, DP batches not marked graph-safe, invalid encoder/TBO/ngram layouts, and batches beyond the largest bucket. Plain decoder-only CosyVoice primarily depends on bucket admission plus any enabled DP/TBO conditions.

Capture builds a dummy `ForwardBatch` entirely on stable buffers (`869-1025`), warms kernels, restores sequence sentinels, resets index buffers, freezes GC by default, iterates large-to-small buckets, initializes out-of-graph and in-graph attention metadata, executes the real model forward, and stores one captured artifact/output per shape key (`1027-1267`). `FullCudaGraphBackend.capture_one` performs two synchronized/barriered warmups, then captures a `torch.cuda.CUDAGraph` in a shared graph memory pool and retains the returned output object (`full_cuda_graph_backend.py:49-143`).

Replay `load_batch` (`1276-1442`) rounds raw batch size up to a captured bucket, fills stable buffers/registry, pads sequence metadata/cache slots using backend sentinels, initializes replay attention metadata, and selects the graph key. `execute` (`1449-1515`) publishes shared-read events according to backend contract, replays, and returns a fresh `LogitsProcessorOutput` view sliced to `raw_num_token`. The full backend's replay simply calls `CUDAGraph.replay()` and returns its persistent captured output object (`full_cuda_graph_backend.py:146-162`). CosyVoice's own `nn.Linear` logits tensor is consequently part of the captured allocation/output; it does not use upstream `next_token_logits_buffer` because its forward bypasses `LogitsProcessor._copy_logits_to_buffer`.

`DecodeInputBuffers.create` allocates device buffers for maximum batch/token geometry and a CPU `seq_lens_cpu` mirror; its populated fields and copy grouping are described at `runner_utils/buffers.py:96-352`. The decode registry adopts those allocations and mirrors `ForwardBatch` fields through named `GraphSlot`s (`cuda_graph_buffer_registry.py:1-800`). Each replay resets padded tails by policy, batches GPU copies by source/destination dtype through `torch._foreach_copy_`, copies CPU slots separately, then runs computed-slot hooks. Decode sequence lengths use a backend sentinel; positions, request indices, cache locations, and optional Mamba indices are zeroed. Input IDs keep their padded tail because that tail is not read. `extract_buffer` returns a dataclass replacement whose tensor fields are slices of the stable allocations. `share_input_buffer` coalesces exact `(name,numel,dtype,device)` matches across eager and graph runners so captured addresses remain stable (`input_buffers.py:1-98`). Prefill-registry behavior occupies `cuda_graph_buffer_registry.py:801-982` but is not reached by CosyVoice custom prefill.

## Sampling semantics and host synchronization

CosyVoice fixes the default sampling backend to PyTorch. `SamplingBatchInfo.from_schedule_batch` (`sampling_batch_info.py:87-222`) makes device tensors for temperatures `[bs,1]`, top-p/top-k/min-p `[bs]`, and optional seeds/logit bias. `top_k <= 1` defines greedy rows; `is_all_greedy` sends the whole batch down argmax. It constructs frequency, presence, repetition, and min-new-token penalizers. `_preprocess_logits` updates grammar masks, applies additive/scaling penalties and grammar masks, then logit bias; it releases the grammar-mask tensor after applying it (`model_runner.py:1812-1838`; `sampling_batch_info.py:240-322`). Custom codec suppressions are applied first in Omni.

`Sampler.forward` spans `sampler.py:114-278`. It applies custom processors and NaN sanitization. All-greedy uses `torch.argmax` on CUDA unless the eligible ROCm AITER path is active. Non-greedy divides logits by per-row temperature in place, softmaxes in place, then:

* with no top-k/top-p/min-p filtering, uses `torch.multinomial`, or deterministic MurmurHash/Gumbel argmax when a seed exists;
* with the configured PyTorch backend, sorts probabilities descending, zeros ranks outside top-k and cumulative top-p, optionally zeros values below `max_probability * min_p`, and samples the remaining weights;
* with FlashInfer, uses FlashInfer sampling and legacy `sgl_kernel` top-k/top-p renormalization for min-p combinations; seeded filtered sampling is rejected.

The PyTorch top-p comparison keeps entries while cumulative mass *before* the current entry is at most `top_p`; top-k uses rank `< top_k`; min-p uses the first sorted probability times per-row `min_p` (`sampler.py:597-715`). Deterministic sampling hashes `(uint64 seed, position, vocab column)` with the in-tree Triton MurmurHash kernel, maps uint32 values to float64 uniform values, applies the Gumbel transform, adds float64 log probabilities, and argmaxes (`sampler.py:717-780`; `kernels/ops/sampling/murmur_hash.py:1-121`). Default TP token synchronization is off; it all-reduces MIN only when `SYNC_TOKEN_IDS_ACROSS_TP` is set or grammars are active (`sampler.py:527-542`).

Logprob output, sampling-mask reporting, Ascend paths, custom backend registration, and helper functions span `sampler.py:332-833`. They are supported mechanics, not demonstrated CosyVoice runtime branches. Likewise `LogitsProcessorOutput` is the shared carrier (`logits_processor.py:178-235`), while standard pruning/LM-head/logprob mechanics occupy `238-1247` and are bypassed by the CosyVoice model head.

The unavoidable host boundary visible in this model is `_collect_tokens: token_ids.tolist()` (`model_runner.py:96-110`). On CUDA that operation waits for and copies the entire batch once; it replaces per-row `.item()` calls but is still a per-generation-step host synchronization before code buffering/emission. The configured `disable_overlap_schedule=True` means the upstream overlap scheduler path is disabled by the builder default. The generic Omni base also provides pinned ping-pong D2H/event staging for other asynchronous paths, but CosyVoice does not override the launch/resolve hooks and this report does not claim that async lookahead is active.

## Kernel dispatch and the `sglang.kernels` transition

`BaseFusedOp` is the new unified namespace contract (`kernels/fused_op.py:1-680`): explicit backend, global forced backend, out-of-tree override, eligible optimized backend priority, platform-specific method, then native fallback. The selected static path is cached per instance; explicit/forced choices remain per call. This infrastructure exists alongside the AOT `sgl_kernel` package.

The AOT package is also in the SGLang v0.5.19 tree at `python/sglang/kernels/aot`, rather than in a separate checkout. Its distribution name is `sglang-kernel`, its import package is `sgl_kernel`, and both `aot/pyproject.toml` and `sgl_kernel/version.py` declare `0.4.6.post1`; SGLang's `python/pyproject.toml` pins that exact distribution version. The main SGLang package configuration explicitly excludes `sglang.kernels.aot` from package discovery and wheel contents (`python/pyproject.toml:212-248`), so this co-located source is packaged separately. CUDA engine startup asserts the same installed distribution version unless `SGLANG_SKIP_SGL_KERNEL_VERSION_CHECK` is set (`entrypoints/engine.py:1700-1719`). Importing `sgl_kernel` selects `sm90/common_ops.*` for compute capability 90 and `sm100/common_ops.*` otherwise, falls back to a package-root extension and then a standard `common_ops` import, and re-exports the elementwise and sampling APIs (`aot/python/sgl_kernel/{__init__,load_utils}.py`). This source evidence does not identify a live environment's installed wheel path or prove its installed version; no import or installation was performed.

For reachable Qwen RMSNorm, `RMSNorm` is a `BaseFusedOp` but defines platform methods rather than registered backend capabilities (`layernorm.py:439-982`). On CUDA, ordinary no-residual RMSNorm calls `sgl_kernel.rmsnorm`; fused residual RMSNorm calls `sgl_kernel.fused_add_rmsnorm`. Those AOT Python APIs use installed `flashinfer.norm` for fp16/bf16 outside Dynamo tracing, and otherwise call registered `torch.ops.sgl_kernel` kernels; PDL defaults from the architecture (`aot/python/sgl_kernel/elementwise.py:1-164`). The AOT binding source validates last-dimension contiguity, matching two-dimensional input/output and one-dimensional weight shapes, same-device placement, selects the current device/stream, and dispatches `flashinfer::norm::RMSNorm` (`FlashInfer csrc/norm.cu:1-48`).

`flashinfer::norm::RMSNorm` chooses vector width as `gcd(16 / sizeof(T), hidden_size)`, caps a row block at 1,024 threads, uses one block per batch row, and allocates one fp32 partial sum per warp. Each thread vector-loads its columns, accumulates squares in fp32, performs warp-shuffle then cross-warp shared-memory reduction, computes `rsqrt(sum_sq / hidden_size + eps)`, reloads input/weight, and writes the weighted result. CUDA 12+/SM90+ emits PDL wait/launch-dependent instructions, while the launcher controls permission through `cudaLaunchAttributeProgrammaticStreamSerialization` (`FlashInfer include/flashinfer/norm.cuh:27-142`). No host read or device synchronization occurs in this path.

The AOT fused source checks CUDA/device, 2-D input/residual, 1-D matching weight, dispatches fp32/fp16/bf16, and calls FlashInfer `FusedAddRMSNorm` on the current stream (`aot/csrc/elementwise/fused_add_rms_norm_kernel.cu:1-59`). The FlashInfer fused kernel stores the rounded `input + residual` back to residual, retains the unrounded fp32 sum in dynamic shared memory, reduces its squared norm, and overwrites input with the normalized weighted result; dynamic shared storage covers the hidden row plus aligned warp sums (`FlashInfer include/flashinfer/norm.cuh:144-270`). SGLang compiles ordinary AOT RMSNorm from FlashInfer's `csrc/norm.cu` and includes this header from the pinned commit (`aot/CMakeLists.txt:74-80,257-321`).

The newer in-tree JIT fused-add implementation is selected only for the `cast_x_before_out_mul=True` branch and supported fp16/bf16 shapes, which ordinary Qwen constructs do not request. Qwen passes `quant_linear`, permitting FlashInfer fused norm+FP8 quant only when the downstream quant method exposes eligible static per-tensor FP8 state. Native fallback computes variance in fp32. The JIT public APIs and conditions are `rmsnorm(input,weight,out=None,eps)` for supported hidden sizes and `fused_add_rmsnorm(input,residual,weight,eps,cast_x_before_out_mul=False)` for positive multiples of 16 up to 8192 (`kernels/ops/layernorm/norm.py:1-179`); their CUDA source validates 2-D layouts/dtypes and launches one token row per block or occupancy-bounded grids (`kernels/jit/csrc/elementwise/{rmsnorm,fused_add_rmsnorm}.cuh`). HF-cast RMSNorm has its separate fp16/bf16, 2-D, hidden-size-gated API (`rmsnorm_hf.py:1-79`).

For reachable Qwen SiLU, `SiluAndMul.forward_cuda` allocates half-width output and invokes a module-level dispatcher. That dispatcher prefers the new `sglang.kernels.ops.activation.silu_and_mul(input,out)` when output hidden width is divisible by the architecture vector width (32 bytes on SM100+, 16 bytes earlier), otherwise falls back to `sgl_kernel.silu_and_mul` (`activation.py:54-105,130-184`). The new API accepts an optional output and optional expert filter, flattens to 2-D, and JIT-loads `elementwise/activation.cuh` (`kernels/ops/activation/activation.py:1-229`). The JIT source computes gate activation and multiplication in fp32 then casts to input dtype, validates `input_width == 2 * output_width`, vector divisibility, and 32-bit indexing bounds (`kernels/jit/csrc/elementwise/activation.cuh:1-287`). The AOT fallback API requires the last-dimension byte size to be 16-byte aligned and dispatches `torch.ops.sgl_kernel.silu_and_mul`; its CUDA source launches one block per token and the FlashInfer `act_and_mul_kernel` with 16-byte vector width on the current stream (`aot/python/sgl_kernel/elementwise.py:248-270`; `aot/csrc/elementwise/activation.cu:1-170`).

For sampling, the current CUDA imports in `layers/sampler.py` use FlashInfer for sampling and `sgl_kernel.top_k_renorm_prob/top_p_renorm_prob`. The AOT aliases accept scalar or per-row thresholds, cast probabilities to fp32, and delegate to `flashinfer.sampling` when that module imports; only MUSA or absence of FlashInfer invokes the registered AOT renormalization ops (`aot/python/sgl_kernel/sampling.py:1-115`). Those registered ops bind to FlashInfer functions (`aot/csrc/common_extension.cc:346-356`). Their translation unit requires a 2-D fp32 probability tensor, selects the tensor device/current stream, and calls `TopKRenormProb<float,int>` or `TopPRenormProb<float>` with either a per-row threshold pointer or scalar threshold (`FlashInfer csrc/renorm.cu:1-61`).

Both renormalizers launch one block per batch row and choose vector width as `gcd(4, vocab_size)`. Top-p uses 1,024 threads. Its `p >= 1` path sums the whole row and multiplies by the reciprocal of that sum when it exceeds `1e-8`, otherwise by 1. Otherwise it searches a probability threshold using two pivots and repeated block reductions while maintaining the mass-above-threshold invariant; it terminates when the adjacent probability bounds meet, retains values strictly greater than the lower threshold, and scales by `1 / max(retained_mass, 1e-8)` (`FlashInfer include/flashinfer/sampling.cuh:1570-1748,1981-1999`). Top-k uses 1,024 threads on compute capability 8+ and 512 below it. When `k < vocab_size`, it applies the analogous two-pivot search using both count and mass reductions, retains values strictly greater than the resulting threshold, and normalizes by retained mass; when `k >= vocab_size`, it uses the initialized negative-infinity threshold and unit scale (`sampling.cuh:1859-2023`). Both enqueue on the current stream without a host read or explicit synchronization.

SGLang's AOT build obtains `csrc/renorm.cu` and `include/flashinfer/sampling.cuh` from the pinned FlashInfer commit (`aot/CMakeLists.txt:74-80,305-321`). In-tree Triton renormalizers exist (`kernels/ops/sampling/renorm_triton.py` and `top_p_renorm_triton.py`) but are not imported by this sampler and therefore are not on the reached CosyVoice path. A live installed wheel remains an external evidence boundary.

## Facts versus unresolved runtime/external evidence

Facts: CosyVoice prefill is eager/custom and reports graph false; decode is eligible for upstream decode graphs; its default sampler is PyTorch; overlap scheduling defaults disabled; each sampled step reaches a batched `.tolist()` before code collection; the head is a plain non-vocabulary-parallel `nn.Linear`; and the Qwen backbone uses the selected runtime attention backend plus SGLang linear/norm/activation dispatch.

Unresolved: actual checkpoint dimensions/dtype/quantization, TP/DP/PP sizes, effective overrides, attention backend, graph bucket list after configuration resolution, whether a live decode met graph admission, active kernel choices, graph capture success, stream timing, D2H duration, or GPU utilization. The live installed `sglang-kernel` wheel, PyTorch CUDA internals, and backend-specific attention implementation internals were not read completely. No numerical identity beyond explicit branch/code contracts is asserted.
