## Configured graph and ownership

The checkpoint config fixes a 24 kHz model, 25 speech tokens/s, two mel frames/token, 192-wide input speaker embedding, and 80-bin mel features (`cosyvoice3.yaml:7-18`). Its reachable synthesis graph is:

`CausalMaskedDiffWithDiT.inference` -> `PreLookaheadLayer` -> `CausalConditionalCFM.forward/solve_euler` -> `DiT.forward` -> 22 `DiTBlock`s -> `CausalHiFTGenerator.inference` -> `CausalConvRNNF0Predictor` + `SourceModuleHnNSF` -> causal upsample/residual stack -> ISTFT.

The configured Flow has `pre_lookahead_len=3`; DiT has width 1024, depth 22, 16 heads of width 64, feed-forward multiplier 2, 80-wide mel/mu/speaker inputs and output, a 50-mel-frame static chunk, and `num_decoding_left_chunks=-1` (`cosyvoice3.yaml:38-75`). The configured CFM uses `sigma_min=1e-6`, Euler, cosine time scheduling, training CFG drop rate 0.2, and inference guidance rate 0.7 (`cosyvoice3.yaml:52-64`). HiFT uses channels 80 -> 512, eight harmonics, rates `[8,5,3]`, kernels `[16,11,7]`, ISTFT FFT 16/hop 4, three residual kernels per upsample stage, right lookahead 4 at its input, and audio clamp 0.99 (`cosyvoice3.yaml:77-100`). The resulting nominal mel-to-wave stride is `8*5*3*4 = 480` samples/frame, exactly what Omni derives (`stages.py:593-608`).

Omni owns two paths. Buffered decoding packs one or more requests and calls its own `_generate_flow` and `_solve_flow_euler`, then batches length-compatible HiFT inputs (`stages.py:134-199,251-298,340-431,994-1036,1195-1219`). Streaming singleton hops call the native pinned Flow signature, while multi-request equal-shape hops use the packed causal adapter (`stages.py:1066-1129`; `streaming_vocoder.py:620-696`). Both then use the same causal HiFT object.

## Flow input, lookahead, and mel layout

Native `CausalMaskedDiffWithDiT.inference` accepts one request and asserts batch 1. It normalizes `[1,192]` speaker input along dimension 1 and projects it to `[1,80]`. It concatenates prompt and generated tokens to `[1,P+G]`, constructs a non-padding mask from the supplied summed length, embeds clamped token IDs to `[1,P+G,80]`, and zeros masked embeddings (`flow.py:370-388`).

`PreLookaheadLayer` first transposes `[B,T,80]` to `[B,80,T]`. Its first convolution maps 80 -> 1024 with kernel 4. Finalized inference right-pads three zero frames, preserving T outputs. Non-final inference separates the final three embeddings as explicit context and convolves the preceding body plus those three frames, producing `T-3` outputs. A leaky ReLU follows. A second 1024 -> 80 kernel-3 convolution gets two zeros on the left, so it uses the current and two preceding first-convolution outputs. The result is transposed and added to the original body (`upsample_encoder.py:66-103`; `flow.py:390-395`). Each result frame is repeated twice, yielding `[B,2T,80]` when finalized and `[B,2(T-3),80]` otherwise.

For native inference, `mel_len1=P*2` is supplied by prompt features and `mel_len2=h.length-mel_len1`. Conditioning is `[1,80,mel_len1+mel_len2]`, with the prompt feature in the leading `mel_len1` frames and zeros after it. The decoder output is sliced after the prompt and asserted to have `mel_len2` target frames (`flow.py:396-414`). There is no Flow cache in this configured class; it returns `None`.

Omni's packed path validates each token `[1,G]`, prompt token `[1,P]`, prompt feature `[1,2P,80]`, and embedding `[1,192]`; it copies them onto the Flow parameter device, uses int32 tokens, and uses the Flow parameter dtype for prompt features and embeddings (`stages.py:93-199`). Rows are left aligned and token padding is zero. A boolean `[B,Tmax,1]` length mask zeros token embeddings, so token ID zero in padded slots is not semantically active. Finalized lookahead is applied to the whole padded tensor. Causal packed lookahead handles unequal valid lengths row by row so each row's three-frame context comes from its valid end, then right-pads the shorter resulting hidden sequences (`stages.py:202-248`). Repetition and transpose form contiguous `mu [B,80,Mmax]`. Its numeric mask is `[B,1,Mmax]`, true/one before each row's valid output length and false/zero after it (`stages.py:340-381`). Prompt conditioning is copied to the leading prompt frames. Generated rows are finally sliced from `prompt_frames` through the row's valid total and shape-checked against target tokens times two (`stages.py:412-431`).

## Noise, time steps, Euler, and CFG pairing

`CausalConditionalCFM.__init__` calls `set_all_random_seed(0)` and creates a plain CPU tensor `rand_noise [1,80,15000]` (`flow_matching.py:196-200`; `common.py:181-185`). It is neither a parameter nor registered buffer. Native forward slices its prefix to the mel length, copies it to mu's device and dtype, and scales by temperature, whose default is 1.0 (`flow_matching.py:203-227`). Omni performs the same slice and transfer, expands it across batch, and clones it (`stages.py:387-398`). Thus inference uses a fixed shared initial-noise prefix for all requests; it does not draw fresh Flow noise per call. A mel length above 15,000 gets an explicit Omni error. The native code relies on slicing behavior and later shape compatibility.

Ten Euler steps use 11 points from 0 through 1 in mu's device and dtype. With the configured cosine scheduler, each point `s` becomes `1-cos(pi*s/2)`, so step widths are nonuniform (`flow_matching.py:224-227`; `stages.py:399-405`). Each step evaluates at the current point and applies `x <- x + dt*v`; the returned mel is forced to float32 (`flow_matching.py:71-124`; `stages.py:251-298`).

Native inference hardcodes solver workspaces to `[2,80,T]`, mask `[2,1,T]`, speaker `[2,80]`, and cond `[2,80,T]`. Both x rows and both mask rows are populated. Only row 0 receives mu, speaker, and cond; row 1 remains zero for those three inputs. The two estimator results are split conditional then unconditional, and combined as `(1+r)*conditional-r*unconditional`, with `r=0.7` (`flow_matching.py:93-124`). Omni generalizes the same pairing to `2B`: first B rows receive mu/speaker/cond, second B rows keep zeros; x and mask are duplicated. It uses a one-element timestep tensor that broadcasts through the DiT modulation over all `2B` rows (`stages.py:251-298`). The native workspace has a two-element timestep tensor. Both rows receive the same scalar time.

Training mechanics are separate from reachable inference: random `t [B,1,1]`, fresh Gaussian z, interpolant `y=(1-(1-sigma_min)t)z+t*x1`, target velocity `u=x1-(1-sigma_min)z`, and independent per-row CFG retention of mu/speaker/cond before masked MSE (`flow_matching.py:155-193`).

## DiT forward and exact masks

DiT transposes x, mu, and cond from `[B,80,L]` to `[B,L,80]`. `InputEmbedding` concatenates x, cond, mu, and a time-repeated `[B,80]` speaker vector, giving `[B,L,320]`, and linearly projects to `[B,L,1024]` (`dit.py:76-98,145-157`). It adds a causal convolutional position signal: two group-16 kernel-31 convolutions, each preceded by 30 zeros on the left, each followed by Mish. This positional branch therefore has no future input and has at most 60 prior positions through its two convolutions (`modules.py:115-144`). Timestep embedding computes 128 sine and 128 cosine components from `1000*t` frequencies, preserves the input timestep dtype after the trigonometric construction, and maps 256 -> 1024 -> 1024 with SiLU (`modules.py:71-83,606-616`). RoPE is obtained for sequence length L from pinned x-transformers (`dit.py:129,158`; `modules.py:367-373`; x-transformers `x_transformers.py:698-780`).

CosyVoice constructs `RotaryEmbedding(dim_head)` with `dim_head=64` and all x-transformers defaults: xPos disabled, interpolation factor 1, base 10,000, and base-rescale factor 1 (`dit.py:104-143`; x-transformers `x_transformers.py:698-727`). Construction creates a persistent float32 `inv_freq [32]` buffer with element `j` equal to `1 / 10000^(2j/64)`. Moving DiT moves this buffer to the DiT device. `forward_from_seq_len(L)` obtains integer positions `[0,...,L-1]` on that device and calls `forward` (`x_transformers.py:729-736`). The CUDA-autocast-disabled forward converts positions to the inverse-frequency dtype, takes their outer product to `[1,L,32]`, duplicates every frequency adjacently and flattens to `freqs [1,L,64]`. Since xPos is disabled, it returns `(freqs, 1.0)`; its computed `max_pos` has no effect on this branch (`x_transformers.py:735-754`). The operation creates fresh position and frequency tensors each DiT invocation; only `inv_freq` persists.

CosyVoice's `AttnProcessor` applies `apply_rotary_pos_emb` separately to query and key while each still has layout `[B,L,1024]`, before reshaping to `[B,16,L,64]` (`modules.py:360-380`). In x-transformers, `rot_dim=64`; it selects the final L frequency positions, leaves scalar scale at 1.0, splits the projected tensor into `t_rotated [B,L,64]` and `t_unrotated [B,L,960]`, and rotates only the first part (`x_transformers.py:763-780`). `rotate_half` groups adjacent pairs `(a,b)` and returns `(-b,a)` (`x_transformers.py:756-760`), so a pair at angle theta becomes `(a*cos(theta)-b*sin(theta), a*sin(theta)+b*cos(theta))`. The untouched 960 channels are concatenated back. Consequently, after the later head reshape, the complete first attention head is rotary-positioned and the other 15 heads are unchanged. The CUDA-autocast-disabled function casts its final concatenated output back to each query/key tensor's original dtype. Its four-dimensional frequency-broadcast branch is not reached because CosyVoice calls it on three-dimensional tensors.

The exact non-streaming mask starts from input validity `[B,1,L]`. `add_optional_chunk_mask` sees no dynamic or static chunk and returns that tensor. DiT repeats it over query positions to `[B,L,L]`, then adds a singleton head dimension `[B,1,L,L]` (`dit.py:165-166`; `mask.py:161-236`). A true boolean means an allowed key to PyTorch scaled-dot-product attention (`modules.py:382-391`). Thus every valid or padded query uses all valid keys and no padded keys; attention is bidirectional over the valid utterance.

The streaming mask calls the same helper with static chunk 50. For query index q and key index k, `subsequent_chunk_mask` permits `k < (floor(q/50)+1)*50`. It therefore exposes every prior chunk and the entirety of q's current 50-frame chunk, including positions later than q within that chunk. Although the config passes `num_decoding_left_chunks=-1`, this implementation explicitly ignores that argument and always retains all earlier chunks (`mask.py:127-158`). The `[L,L]` chunk mask is ANDed with `[B,1,L]` key validity by broadcast, producing `[B,L,L]`; DiT adds the head singleton (`mask.py:223-229`; `dit.py:163-164`). If any query row has zero allowed keys, the helper prints to stdout and replaces that entire row with true (`mask.py:232-236`). With the configured static mask and nonempty valid inputs, earlier keys are available.

Each of 22 blocks performs adaptive LayerNorm modulation from the timestep into attention shift, scale, and gate, applies 16-head SDPA after q/k RoPE, gates the residual, then applies a similarly shifted/scaled LayerNorm, a 1024 -> 2048 -> 1024 GELU-tanh feed-forward, and a gated residual (`modules.py:230-244,271-282,289-407,500-530`). SDPA dropout is hardcoded to 0; the output projection's configured default dropout is 0.1 but eval mode disables it. When passed the four-dimensional DiT mask, `AttnProcessor` uses it directly for SDPA, then derives `[B,L,1]` output validity from `mask[:,0,-1]` and zeros the projected attention result at disallowed sequence positions (`modules.py:382-405`). Residual state itself is not zeroed there. After all blocks, a final timestep-modulated LayerNorm and 1024 -> 80 projection returns `[B,80,L]` (`dit.py:168-176`). DiT has no key/value cache or other per-request mutation; every Euler evaluation recomputes every block over the supplied prefix.

`MelSpec`, `TextEmbedding`, `ConvPositionEmbedding`, `ConvNeXtV2Block`, joint-attention classes, and MMDiT are present in the fully read DiT modules but are not instantiated by this checkpoint's DiT graph. Matcha's `BASECFM` imports its generic `Decoder`, but `ConditionalCFM` replaces `self.estimator` with the configured CosyVoice DiT; the generic Matcha decoder is not instantiated on this graph (`flow_matching.py:21-34`; Matcha `flow_matching.py:12-30`).

## Causal HiFT forward, FFT, and deterministic source state

`CausalHiFTGenerator.inference` first mutates the f0 predictor module to float64, casts the mel input to float64, predicts f0, and converts f0 back to the original mel device and dtype (`generator.py:713-726`). `CausalConvRNNF0Predictor` uses a right-causal kernel-4 convolution (three right-context frames), followed by ELU, then four left-causal kernel-3 convolutions with ELU, and an absolute-valued 512 -> 1 classifier (`f0_predictor.py:62-103`). Finalized calls supply three zeros on the right. Non-final calls remove the last three mel frames from the main input and pass them as the exact right context to the first convolution. Causal HiFT also removes those three frames from the mel input passed to its decoder, so f0 and decoder inputs remain length-aligned (`generator.py:714-726`).

F0 is nearest-neighbor upsampled by 480. At 24 kHz, `SourceModuleHnNSF` selects causal `SineGen2` with nine components (fundamental plus eight harmonics) (`generator.py:609-619`). In eval causal mode, SineGen2 uses constructor-created fixed `rand_ini [1,9]` (fundamental phase forced to zero) and fixed `sine_waves [1,7,200,000,9]` as its noise source. SourceModule has another fixed constructor-created `uv [1,7,200,000,1]` used as its noise branch (`generator.py:208-226,233-317,338-375`). These are ordinary attributes rather than buffers. Calls slice prefixes and copy relevant tensors to the input device. Batch dimension 1 broadcasts across a larger inference batch. No fresh runtime random draw occurs in eval causal source generation; construction consumes the then-current random state. Separately, the CFM constructor resets global Python, NumPy, CPU Torch, and CUDA Torch seeds to zero.

The source waveform is transformed by `torch.stft` with FFT/window 16, hop 4, a periodic Hann window created by SciPy, complex output, and PyTorch defaults including centered framing. Real and imaginary `[B,9,S]` tensors concatenate to `[B,18,S]` (`generator.py:491-497,668,672-680`). The Hann tensor is a plain CPU attribute and is copied to the source device in both STFT and ISTFT calls.

The decoder's mel branch begins with right-causal kernel 5, 80 -> 512. Finalized calls use four right zeros. Non-final calls remove four trailing mel frames from the main input and pass those frames as right context. It also removes `120*4=480` terminal STFT frames from each source real/imag tensor (`generator.py:621-623,672-680`). Three causal nearest-neighbor upsample-convolution stages use rates 8, 5, 3 and kernels 16, 11, 7, reducing channels 512 -> 256 -> 128 -> 64. Each `CausalConv1dUpsample` repeats samples, left-pads `kernel-1`, and applies stride-1 convolution, preserving the upsampled length (`convolution.py:224-258`; `generator.py:625-637,682-700`).

At every stage, a source branch downscales the 18-channel source with cumulative factors 15, 3, and 1, maps it to the corresponding mel-branch channel width, and applies a causal residual block before addition (`generator.py:639-655,689-700`). Each main stage averages three causal residual-block outputs with kernels 3, 7, and 11. Every residual block has three dilation pairs (1,3,5): Snake activation, a left-causal dilated convolution, Snake, a left-causal dilation-1 convolution, and a residual add (`generator.py:46-122,658-662`). Snake applies `x + sin(alpha*x)^2/(alpha+1e-9)` with trainable channel-wise alpha (`activation.py:34-84`). Causal convolution computes its full receptive padding, creates zeros when no explicit context is supplied, concatenates left or right as configured, and returns an output with the same input time length (`convolution.py:150-187`). None of these generator convolutions carries a mutable streaming cache in this path.

After a left-causal kernel-7 projection to 18 channels, channels 0:9 become magnitude by exponentiation and channels 9:18 become a phase angle by sine (`generator.py:702-707`). Magnitude is clipped to at most 100; real and imaginary are `magnitude*cos(phase)` and `magnitude*sin(phase)`. `torch.istft` uses FFT/window 16, hop 4, the same Hann window, and PyTorch defaults (`generator.py:499-505`). A non-final decode drops the last 480 waveform samples; every result is clamped to [-0.99,0.99] (`generator.py:707-711`).

The generator object carries fixed source/noise tensors and model parameters, but no evolving request cache. Omni streaming state instead retains the entire accumulated mel tensor (detached, on its current device) and an integer emitted-sample offset. On each hop it concatenates all prior mel with the new Flow suffix, reruns causal HiFT on the complete accumulated mel, copies only waveform samples after the prior offset to CPU, and advances the offset to the complete waveform length (`stages.py:1131-1144`; `streaming_vocoder.py:684-695,757-795`). Whole-utterance decoding calls HiFT once with `finalize=True`. Buffered HiFT batching right-zero-pads mel rows to the group's maximum, invokes HiFT once, and crops each row to `mel_length*480` (`stages.py:1195-1219`).

## Streaming context and official-reference differences

Omni keeps all generated tokens for the request. A non-final Flow window is the complete prefix through `token_offset + hop + 3`; Flow consumes the final three as lookahead and emits the earlier prefix. Hops start at 25 tokens and grow by two after a successful hop to a maximum of 100 unless growth is disabled (`streaming.py:12-26,49-94`; `streaming_vocoder.py:698-755`). The DiT recomputes that complete emitted prefix at every Euler step, with 50-frame chunk attention and all earlier chunks visible. The final leftover uses `finalize=True` and, by the Omni constant, non-streaming/bidirectional DiT attention (`streaming.py:23-26`; `streaming_vocoder.py:735-755`). Whole utterances also use finalized pre-lookahead and bidirectional DiT.

The official `CosyVoice3Model` likewise retains all mel history and a speech offset, concatenates the full mel history, reruns causal HiFT, and emits the suffix after the prior sample count (`cli/model.py:397-450`). Its inherited `CosyVoice2Model.tts` retains all speech-token history and submits complete prefixes with three lookahead tokens (`cli/model.py:328-394`). It computes prompt padding and enlarges only the first generated-token hop by that amount so the prompt-plus-body boundary reaches a 25-token multiple (`cli/model.py:343-360`). Omni instead physically pads prompt token and prompt mel tensors to a 25-token multiple by repeating the last token and last mel frame, then keeps the first generated hop at 25 (`streaming.py:110-154`; `streaming_vocoder.py:492-524`). This changes the actual conditioning prefix and first-hop token count while preserving the intended 50-mel chunk alignment.

The official reference runs every request separately because native Flow asserts batch 1. Omni can group causal hops with the same `(hop_len, token_offset)` even when prompt lengths differ, performs one `2B` CFG DiT call per Euler step, then runs HiFT per request for streaming (`streaming_vocoder.py:370-434,570-696`). Buffered mode can also pack differing utterance lengths for Flow and group padded HiFT calls (`stages.py:830-936,994-1036`).

The official `CosyVoice3Model` maintains its per-request mel/speech-offset dictionaries. Its inherited TTS loop updates `self.token_hop_len` on the model object after a hop (`cli/model.py:328-394`), whereas Omni stores `hop_len` in each `_CosyVoice3StreamState` (`streaming_vocoder.py:41-52,126-135`). Omni releases token, mel, prompt, and speaker tensors when a stream ends (`streaming_vocoder.py:851-859`). Omni also folds all weight-normalization parametrizations into HiFT once at load; the pinned official model loader only loads and evals the model (`stages.py:583-622,646-669`; `cli/model.py:65-73`).

## Device, dtype, allocation, and synchronization facts

The loader moves Flow and HiFT to the resolved device and eval mode. Default Omni Flow autocast is bfloat16; default HiFT autocast is disabled/float32 (`stages.py:646-669,1245-1300`). Packed host tensors are copied to the Flow device. Packed prompt/embedding buffers use the Flow parameter dtype outside operation-specific autocast behavior. The fixed CFM noise is copied from CPU for every call. CFM solver workspaces allocate on x's device in the speaker result dtype. Its returned mel is explicitly float32. Default HiFT then receives float32 mel; f0 computation changes its predictor parameters and inputs to float64 on every call and converts the f0 result back.

Streaming HiFT history remains device-resident because `_hift_delta` detaches but does not move the retained mel; emitted waveform deltas call `.cpu()`, creating the device-to-host boundary (`stages.py:1131-1144`). Buffered outputs detach and move cropped waveforms to CPU (`stages.py:1183-1219`). The debug Flow timer records accelerator events without synchronizing and logs only if the end event has completed by the later HiFT/host point (`stages.py:301-336,477-491`). The official raw TensorRT estimator path synchronizes the current CUDA stream before switching, runs on its acquired stream, synchronizes that stream, then releases the context (`flow_matching.py:126-153`); Omni's PyTorch path has no explicit synchronization in the model internals reviewed here.

Major per-call allocations are packed token/prompt/embedding buffers, `[2B,...]` CFG workspaces, a cloned expanded noise tensor, mel masks and conditions, DiT q/k/v and block activations, source STFT tensors, and padded HiFT batches. Per-request streaming state grows with the complete token list and complete retained mel history. No cancellation hook exists inside Flow, Euler, DiT, or HiFT; cancellation is observed by the surrounding scheduler between steps/messages (`streaming_vocoder.py:451-490`).

## Existing observability and errors

Omni logs Flow solve batch size and elapsed milliseconds at DEBUG if the nonblocking end-event query succeeds (`stages.py:477-491`). It logs first-hop and follow-up Flow batch size, hop, and offset at INFO (`streaming_vocoder.py:661-674`) and logs folded HiFT parametrization count at INFO (`stages.py:611-622`). Input validation reports malformed tensor ranks/widths, prompt-token/mel ratio mismatch, missing state, unsupported dtype, impossible Flow noise length, unexpected generated shape, invalid hop configuration, and missing prompt/speaker latch at the owning boundaries. The mask helper alone prints an all-false-row repair directly to stdout (`mask.py:232-235`). The pinned external Flow logs only its input frame rate during construction (`flow.py:308-309`). There are no internal per-Euler-step, per-DiT-block, f0, FFT, or HiFT timing/shape metrics in the reviewed source.
