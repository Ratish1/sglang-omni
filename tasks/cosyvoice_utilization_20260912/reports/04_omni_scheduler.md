# Sector 04: Omni scheduler

## Scope and evidence

This is a mechanics-only report for Omni commit `645b472cdb2d7b93a1825a5bfa6a603b62b03936`. Every line of the six assigned files was read. I also read the complete generic engine-construction owner, the complete Fun-CosyVoice3 engine builder and request adapter, and the complete SGLang request-data extension needed to close the reachable Fun-CosyVoice3 scheduler boundary. The pinned upstream SGLang scheduler (`0bcd822377da7b5718e674eaf9c870d349424dd1`, v0.5.19) and `SGLangExecutionBridge` are separately assigned ownership boundaries; this report records the exact names, arguments, values, and state that cross those boundaries without restating their internal implementations. No tests or model runs were performed.

## Ownership and call graph

For Fun-CosyVoice3, `FunCosyVoice3EngineBuilder` derives generation defaults and builds the custom runner and request/result adapters (`sglang_omni/models/fun_cosyvoice3/engine_builder.py:26-143`). `TtsEngineBuilder._build_runtime` creates the runner first, creates the adapters, and passes the infrastructure objects plus those three values to `OmniScheduler` (`sglang_omni/scheduling/engine_factory.py:494-519`). Generic `_make_scheduler` also supplies the builder's abort callback and optional finished callback, then applies extra callback and scheduler kwargs (`engine_factory.py:379-410`). After construction, Fun-CosyVoice3 passes `scheduler.outbox` directly to `model_runner.set_stream_outbox` (`fun_cosyvoice3/engine_builder.py:142-143`).

`OmniScheduler` owns stage-facing queues, ingress routing, request build/admission, waiting/running/last/current batch references, invocation of the custom runner, conversion back to upstream batch results, stage output, abort/admin state, and the serving loop (`sglang_omni/scheduling/omni_scheduler.py:167-2735`). It does not inherit from upstream `Scheduler`. Missing attributes are obtained from the upstream class and callable attributes are bound to the Omni instance (`omni_scheduler.py:732-756`). Direct replacements therefore take precedence; delegated upstream methods execute against Omni's mirrored fields.

The normal loop is:

`Stage -> inbox -> recv_requests -> process_input_requests -> request_builder -> waiting_queue -> upstream get_next_batch_to_run -> custom runner execute -> upstream process_batch_result -> stream_output/result_adapter -> outbox` (`omni_scheduler.py:823-938,1366-1454,1628-1737,2348-2379`).

The async loop replaces `execute` with `execute_launch` and `execute_resolve`, carries one launched step in `_async_pending`, and still routes resolved results through upstream `process_batch_result` (`omni_scheduler.py:1527-1557,2416-2466,2560-2647`).

## Ingress, preparation, admission, and budgets

`IncomingMessage` carries request ID, one of `new_request`, `stream_chunk`, or `stream_done`, and arbitrary data; `OutgoingMessage` carries request ID, `result`/`stream`/`error`, arbitrary data, optional target and metadata (`scheduling/messages.py:10-23`). In TP=1, ingress drains the local queue. With TP>1, only the entry rank drains and all ranks receive the same message list through `broadcast_pyobj` on the TP CPU group from the first TP rank (`omni_scheduler.py:841-863`). A message saved by idle blocking is returned before newly queued messages. Aborted IDs are discarded. New requests clear a completed tombstone; stream messages are routed immediately (`omni_scheduler.py:823-839`).

Stream data arriving before admission is held per request in an insertion-ordered dictionary. Each entry owns a chunk list and done flag (`omni_scheduler.py:78-85,1739-1768`). Completed request IDs suppress later chunks. Existing admitted request data is found by scanning running/current/last/async-pending batches, then the waiting queue (`omni_scheduler.py:2699-2715`). Otherwise a pending entry is created. At 10,000 pending request entries, oldest entries are evicted until 5,000 remain before the new request is inserted (`omni_scheduler.py:2669-2686`). Default chunk handling appends to a lazily created deque; default done handling sets `stream_done=True`; injected handlers replace those operations (`omni_scheduler.py:2717-2735`). Base Omni always reports a deferred build ready and rechecks it on every chunk, while subclasses may override both gates (`omni_scheduler.py:1303-1316`).

Before a build, pending chunks are moved onto `payload.prefetched_chunks`, after existing prefetched chunks, while the pending entry remains to retain its done state. `prefetched_stream_done` is copied from that entry (`omni_scheduler.py:884-903`). When built data is enqueued, the payload's prefetched chunks/done are first applied, then any chunks that arrived during the build are popped from pending ingress and appended; its done flag is applied if it was not already represented (`omni_scheduler.py:1215-1221,1318-1322`).

Request build has two modes. With one configured worker, no executor exists and the scheduler thread calls the builder synchronously. With more than one, a `ThreadPoolExecutor` is created, except TP>1 forces one worker to preserve rank-identical admission order (`omni_scheduler.py:228-261`). The outstanding future limit defaults to worker count and is at least one. The optional build backlog cap is the larger of outstanding limit and positive `max_queued_requests`; without a positive queue limit it is unlimited. `_stage_request_build_payloads` drains backlog first up to outstanding capacity, deduplicates IDs across aborted/build/admission/backlog/current selection, admits new payloads into the selected set, backlog, or rejection set, and accounts against the overall queued limit (`omni_scheduler.py:1009-1084`). Build results are drained in insertion order: if the first stored future is incomplete, later completed futures remain undrained in that pass (`omni_scheduler.py:1086-1117`). Builder start/end profiler events surround only a successful return; exceptions emit an error and abort (`omni_scheduler.py:954-967,929-936,1099-1108`).

The queue-capacity count is waiting requests plus pending build futures, pending deferred admissions, backlogged build payloads, and stream-gated deferred payloads. `max_queued_requests=None` is unlimited; otherwise full means count greater than or equal to the configured integer (`omni_scheduler.py:987-999`). Pre-build rejection emits `QueueFullError("The request queue is full.")` and aborts (`omni_scheduler.py:1001-1007`; `admission.py:7-23`). A second upstream-owned queued-limit check runs after priority default/validation and before appending to `waiting_queue` (`omni_scheduler.py:1223-1247`).

A builder may return `DeferredAdmission(value, ready Future)`. If incomplete it is held by request ID; completed futures are drained under the admission lock, their exception becomes an error plus abort, and a successful value enters normal enqueue (`omni_scheduler.py:1119-1188`; `scheduling/types.py:32-35`). `request_build_queue_fits_workers` is false without an executor; otherwise it compares pending builds plus backlog to worker count, not the pending-future limit (`omni_scheduler.py:940-952`). Idle waiting polls rapidly while either build or deferred admission work exists, polls at 1 ms on TP follower ranks, and otherwise blocks on the inbox for 20 ms (`omni_scheduler.py:969-985`).

On enqueue, token containers are converted to `array("q")`, preserving the identity relation between padded/unpadded arrays (`omni_scheduler.py:1266-1277`). If `enforce_request_limits` is true, upstream initializes/clamps maximum new tokens, upstream input validation runs with auto-truncation disabled, and the resulting integer is copied into request data (`omni_scheduler.py:1279-1290`). Every request, independently of that flag, is rejected if `len(origin_input_ids) + max_new_tokens` exceeds `max_req_len`; the error includes input, requested generation, capacity and a cache-sizing hint selected from worker KV bytes or configured memory fraction (`omni_scheduler.py:1324-1353`). `max_req_len` is `min(context_length - 1, effective_max_total_num_tokens - 1)` and `max_req_input_len` is one less (`omni_scheduler.py:325-337`).

Priority is validated/defaulted before the upstream queued-limit check. Enqueue stamps a prompt-cache key with the current weight epoch when `_omni_prompt_cache_key` exists, emits `scheduler_queue_enter`, stores coalescing time and request-data ownership fields, and appends the `Req` (`omni_scheduler.py:1223-1258`). Successful weight updates increment the epoch and restamp waiting requests (`omni_scheduler.py:1260-1264,2090-2092`). Prefill coalescing is disabled for TP>1. When enabled above one request, it only holds when there is no chunked request, its idle/pending-build gates pass, the waiting count is below the target, and the oldest enqueue has not reached the timeout (`omni_scheduler.py:303-323,1380-1414`).

## Batch execution, result conversion, and output

Each batch launch increments `forward_ct`, assigns `forward_iter`, stamps monotonic launch time, carries whether the scheduler previously idled, then clears the idle marker (`omni_scheduler.py:1430-1436`). A `ScheduleBatch` becomes `SchedulerOutput`: one `SchedulerRequest(request_id=req.rid, data=req._omni_data)` per row plus the original batch as `batch_data` (`omni_scheduler.py:1456-1465`; `scheduling/types.py:22-46`).

The synchronous path emits first-prefill start events, calls `model_runner.execute(SchedulerOutput)`, emits first-prefill end events, invokes the optional per-step stream output builder, and converts `ModelRunnerOutput` to upstream `GenerationBatchResult` (`omni_scheduler.py:1438-1454`). The result has `logits_output=None`, graph eligibility, and reporting token IDs. If `host_token_ids` is present, the synchronous converter uses it instead of device `next_token_ids`; the FutureMap token rail is described as independent (`omni_scheduler.py:1509-1525`; `scheduling/types.py:57-68`). Exceptions are caught by `run_batch`, emit an error/model-path end for every batch request, and abort each with immediate cleanup (`omni_scheduler.py:1416-1421,1559-1566`).

Per-step stream emission is absent when no builder is supplied. Otherwise it indexes `mr_output.outputs` by request ID, suppresses rows in `skip_rids` and aborted IDs, calls the builder with `(rid, request_data, RequestOutput)`, and puts every returned message into the outbox. The first emitted message per request emits `scheduler_first_emit` (`omni_scheduler.py:1467-1498`). A builder object may additionally expose `flush(rid, data)`, whose messages are emitted before the terminal result (`omni_scheduler.py:1500-1507,1675-1692`).

Upstream result processing ultimately calls the installed output streamer. `stream_output` ignores unfinished rows and an optional identity-equal skipped request (`omni_scheduler.py:1628-1640`). Under the admission lock it treats `FINISH_ABORT` or an aborted-ID tombstone as aborted. Normal terminalization atomically claims `_omni_terminal_claimed`, requires live `_omni_data`, and drops stale aliases with no data (`omni_scheduler.py:1641-1663`). Aborted terminal rows run the abort callback, clear first-emit state, emit aborted model-path end, detach data, and emit no result (`omni_scheduler.py:1664-1673`).

For a normal terminal row, the runner's `on_request_finished` runs first, scheduler output IDs, serving weight version, and finish-reason type are copied into request data, stream output is flushed, and the result adapter builds the terminal value (`omni_scheduler.py:1675-1693`). The finished callback runs in `finally`; prefill and decode embedding references are cleared; the model-path interval closes; request data is detached and a completed tombstone is recorded (`omni_scheduler.py:1699-1723,2688-2697`). Terminal errors emit an error. Success emits `OutgoingMessage(type="result")` (`omni_scheduler.py:1725-1737`). Completed tombstones retain up to 10,000 insertion-ordered IDs, evicting one oldest ID when full (`omni_scheduler.py:2661-2667`).

Profiler events owned here are request-build start/end, queue-enter, first emit, first executable-batch prefill start, first executed-batch prefill end with realized batch size, and model-path start/end status (`omni_scheduler.py:954-967,1238-1244,1486-1498,1568-1626`). The prefill start/end sets deduplicate per request and are cleared during terminal or abort cleanup.

## Synchronous and asynchronous loops

The normal loop drains admin requests, receives/broadcasts ingress, re-adds dirty deferred payloads, processes admissions, and sleeps at 1 ms while paused. Otherwise it obtains the upstream-selected batch, runs and processes it if nonempty, or marks idle, resets the new-token tracker, and performs idle waiting. It assigns `last_batch` after the iteration and invokes busy checking only when the strict-memory environment flag is set (`omni_scheduler.py:2348-2379`). `self_check_during_busy` is locally a no-op (`omni_scheduler.py:725-726`).

The overlap loop always raises `NotImplementedError`; construction also forbids enabling both overlap and async decode (`omni_scheduler.py:295-301,2381-2397`). Fun-CosyVoice3 sets upstream `disable_overlap_schedule=True`, and supplies no `enable_async_decode` scheduler kwarg, so it reaches the normal loop under the read construction path (`fun_cosyvoice3/engine_builder.py:60-77,136-143`; `engine_factory.py:468-519`; `omni_scheduler.py:199-210,1770-1780`).

Async decode is one-step lookahead. Eligibility requires a non-null batch, row count at least `async_decode_min_batch_size`, decode mode, and runner approval through `lookahead_eligible`; a missing runner passes that predicate but execution still requires the bound runner (`omni_scheduler.py:2400-2406,2591-2602`). Decode launch emits prefill-start bookkeeping, stamps the batch, builds `SchedulerOutput`, and calls `execute_launch`; `(batch.copy(), sched_output, pending_step)` becomes `_async_pending` (`omni_scheduler.py:1527-1536,2604-2617`). After launching the current step, the prior pending step is resolved and processed. Resolve calls `execute_resolve`; `None` is a failed sentinel; otherwise it emits streams and constructs an upstream result from the resolved step's device `next_token_ids` (`omni_scheduler.py:1538-1557`).

Before resolving, prior-finished or retracted status is snapshotted. Those prior-step rows are suppressed from stream output, corresponding result-token rows are indexed away when nonempty, and request rows are trimmed in lockstep before upstream processing. Rows that become finished during resolve remain so upstream can terminalize them (`omni_scheduler.py:2416-2453`). `_resolve_pending_async` clears ownership before resolve and catches failures (`omni_scheduler.py:2455-2466`). Pause and weight-update administration, transitions to sync/prefill/empty work, and a mixed-chunk scheduling condition drain pending async work first (`omni_scheduler.py:2000,2055,2569-2589,2618-2635`).

After a drain, a batch selected before that drain may contain stale rows. `_drop_stale_overrun` removes finished/retracted rows (`omni_scheduler.py:2468-2558`). Decode rows use `ScheduleBatch.filter_batch` and reslice `out_cache_loc`. Extend rows reject mixed-running-index batches, assert no input/replace embeddings, calculate per-request token segments from `extend_lens`, filter row fields, and then explicitly reslice token IDs or CPU prefill IDs, cache locations, extend lengths/count, prefix lengths, logprob start lengths, and (when enabled) independently segmented logprob token IDs. `decoding_reqs` is restricted by object identity. An empty result becomes `None`.

## Abort, drain, shutdown, and administration

Abort IDs are tombstoned. At 10,000 IDs, oldest IDs are discarded until fewer than 5,000 remain before insertion (`omni_scheduler.py:1817-1830`). Default abort marks a live running/current/last/async-pending request with `to_finish=FINISH_ABORT` and defers cleanup to result processing. Immediate mode instead updates finish state immediately and returns unique matching request objects for explicit KV release (`omni_scheduler.py:1831-1840,2285-2332`). Pending build futures are removed/cancelled, deferred admission is removed, backlog and waiting queue occurrences are removed, request data is detached from waiting rows, pending stream/deferred/dirty/profiler state is cleared, the callback runs when cleanup is immediate, and immediate matched requests release held KV/mamba through `release_kv_cache` (`omni_scheduler.py:1841-1878,2334-2346`). The inbox is drained and all messages for that request discarded while other messages are requeued (`omni_scheduler.py:2649-2659`). Callback exceptions are logged.

`start` records the scheduler thread ID, selects async/overlap/normal loop, closes any remaining model-path intervals in `finally`, shuts down the build executor without waiting while cancelling queued futures, clears deferred admissions, and executes the shutdown callback at most once under a lock (`omni_scheduler.py:1770-1815`). `stop` clears `_running`, deferred admissions, and resources; `event_loop` aliases `start` (`omni_scheduler.py:1791-1808`). Neither `stop` nor `start`'s `finally` calls `_resolve_pending_async`; explicit pending-step drains occur only at the call sites listed in the async-loop and admin mechanics above (`omni_scheduler.py:1770-1815,2455-2466`).

Admin calls from a non-scheduler thread while running enqueue `(action, payload, response_queue)` and wait up to `_admin_timeout_s`, default 300 seconds. The scheduler loop drains all queued operations inline and converts exceptions to failure dictionaries (`omni_scheduler.py:1880-1929`). Supported actions route to model info, pause/continue, three weight-update forms, distributed-group init/destroy, and weight checks. Unknown actions return successful skipped/unsupported data (`omni_scheduler.py:1931-1957`).

Model info merges worker data with topology, pause/queue/build counts, observed pending-build high-water mark, running count, model path/load format, and serving weight version (`omni_scheduler.py:1959-1986`). Pause accepts `abort`, `retract`, or `in_place`, sets paused, drains async work, and respectively aborts all active work, retracts the running batch, or leaves requests in place (`omni_scheduler.py:1988-2014`). Continue optionally empties the CUDA cache and clears pause state (`omni_scheduler.py:2016-2026`). Retraction filters finished rows, calls module-level `retract_all`, clears the batch, requeues each request through the compacting wrapper, and clears chunked state (`omni_scheduler.py:2248-2270`).

Weight update lifecycle pauses, drains async, optionally aborts all requests, otherwise permits active requests only if the previous state was paused in retract mode, calls the worker update, advances prompt-cache epoch on success, optionally flushes cache, optionally empties CUDA cache, and restores or keeps pause according to request/failure mode (`omni_scheduler.py:2028-2147,2235-2241`). Distributed group setup/destruction and checksum actions call corresponding worker methods under `_admin_lock`; group setup is executed inline on the serving thread (`omni_scheduler.py:2149-2188`). Active request enumeration covers build/admission/backlog/waiting plus all live batch aliases and returns sorted IDs (`omni_scheduler.py:2205-2233`). Abort-all deduplicates batch objects, filters them, clears empty `batch_is_full`, and clears `chunked_req` (`omni_scheduler.py:2190-2203`).

## Fun-CosyVoice3 reachable request contract

The CosyVoice preprocessor stores heavy prepared objects in a process-global dictionary keyed by request ID and places only a marker and serialized state into the `StagePayload` (`fun_cosyvoice3/request_builders.py:342-416,704-739`). The scheduler request builder atomically pops that prepared object; absence is an error (`request_builders.py:742-753`). The scheduler abort callback removes a prepared dictionary entry (`request_builders.py:390-392`; `engine_builder.py:139-140`).

The adapter creates an upstream `Req` whose `origin_input_ids` are 63-bit per-embedding-row hashes, sets the projected input embedding marker, tokenizer shim and codec suppression field, and creates `CosyVoice3SGLangRequestData` with the CPU ID tensor, GPU prompt embeddings, output list alias, timing, flow conditioning, original stage payload and stream metadata (`request_builders.py:617-623,742-817`). Maximum generation is explicit when supplied, otherwise `min(2048, 20 * max(target_text_tokens, 1))`; minimum generation is the lesser of twice target tokens and maximum generation. Sampling uses the normalized CosyVoice control-token stop set (`request_builders.py:759-789`). `SGLangARRequestData` supplies the `req`, stage payload, generation counters and model inputs on top of `ARRequestData` (`scheduling/sglang_backend/request_data.py:13-31`; `scheduling/types.py:71-91`).

The result adapter stacks accumulated `output_codes`, converts the final codes to CPU, rebuilds payload state, records prompt/completion counts and elapsed engine time, and returns a new `StagePayload` (`request_builders.py:820-850`). Fun-CosyVoice3 supplies no scheduler `stream_output_builder`; its runner receives the outbox directly after scheduler creation (`engine_builder.py:136-143`). Therefore the generic scheduler per-step `_emit_stream_output` path is inactive for this construction, while runner-owned direct outbox streaming and terminal scheduler result emission remain separate crossings. Runner execution and FutureMap relay details belong to the separately assigned runner/bridge sector.

## Shared pre-LM encoder service

This assigned service is a generic dependency used by ASR encoders; the Fun-CosyVoice3 construction read above does not instantiate it. `QueueEntry` holds an item, future and optional enqueue timestamp (`scheduling/pre_lm_encoder.py:24-28`). `PreLMEncoderService` creates a bounded/unbounded `queue.Queue`, worker-error lock and daemon worker thread; negative max size is rejected (`pre_lm_encoder.py:31-45`). Submission checks worker failure, repeatedly attempts a 100 ms timed put so worker failure can be observed while the queue is full, then propagates a newly observed worker error to the future (`pre_lm_encoder.py:47-81`).

Subclasses own batch selection, encoding, splitting and attachment. Optional hooks control batch context, attach-before-sync (default true), synchronization, staged host copy, caching, retry, error translation, future result transformation, and batch notifications (`pre_lm_encoder.py:83-196`). `_execute_batch` encodes and splits in the batch context, requires one embedding per input, stages all host copies before sync, attaches either before or after one batch synchronization, then caches each result (`pre_lm_encoder.py:137-160`).

The worker repeatedly obtains `(batch, shutdown)`. Empty batch terminates. It records start time, runs the batch, and on failure translates the batch exception. Without retry it fails every future and reports completion. With retry it executes each item as a one-item batch, independently sets result/translated failure, and reports recovered count. Success sets each result and reports completion. A true shutdown flag exits after the current outcome (`pre_lm_encoder.py:259-315`). Notification hook exceptions are only logged. Future invalid-state races are logged; future-result transformation errors become future exceptions (`pre_lm_encoder.py:198-239`). An exception escaping the worker records `_worker_error`, drains queued entries under the lock, and fails the current and queued futures (`pre_lm_encoder.py:241-318`).

## Pipeline state and wire contracts

`PipelineStateBase` owns sample rate and usage counters; subclasses must implement serialization. Tensor serialization detaches and moves tensors to CPU; usage fields are emitted only when truthy (`scheduling/pipeline_state.py:28-62`). Tensor helpers support CPU list encoding, tensor restoration, and lists of tensor items (`pipeline_state.py:65-121`).

`wire` validates emit modes and codecs and stores `_WireSpec` field metadata (`pipeline_state.py:124-179`). Inferred emission is `not_none` only for a literal `None` default, otherwise `always`; explicit modes are `always`, `not_none`, and `truthy`. Codecs cover raw, scalar casts/defaulting, collection casts, CPU-native tensors, tensor-to-list, restored tensors, and tensor-item lists. `typed_tensor` is handled separately through `encode_typed_tensor`/`decode_typed_tensor`; any partially present byte/shape payload or present null component raises, while absent payload uses the dataclass default (`pipeline_state.py:182-200,225-282`).

`DeclarativeStateBase.to_dict` visits all dataclass fields except usage, applies emit and codec rules, then appends nonzero usage. `from_dict` treats non-dicts as empty, restores usage with zero defaults, leaves absent ordinary fields to constructor defaults, and returns `cls(**kwargs)` (`pipeline_state.py:203-282`). `load_state` and `store_state` bridge `StagePayload.data`; `build_usage` returns `None` when all counters are zero, otherwise prompt/completion/total tokens and optional rounded engine seconds (`pipeline_state.py:285-304`).
