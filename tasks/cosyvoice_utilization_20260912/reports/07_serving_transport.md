# Sector 07 — HTTP/output and transport mechanics

## Scope and reachability

This report records code mechanics only. The assigned owner files were read completely at the baseline named in `RESEARCH_CONTRACT.md`. I also read the directly reached coordinator, process-local dispatcher, Fun-CosyVoice3 topology declaration, and media connector interfaces. Stage execution mechanics are deliberately left to the separately assigned pipeline-runtime sector.

The default `FunCosyVoice3PipelineConfig` declares `preprocessing`, `tts_engine`, and `vocoder` with `process="pipeline"`; it explicitly marks `preprocessing -> tts_engine` process-local, and `tts_engine` streams to the same-process `vocoder` (`sglang_omni/models/fun_cosyvoice3/config.py:32-95`). Consequently the default CosyVoice stage-to-stage path uses Python-object dispatch, including its AR-to-vocoder token stream. It does not select `ShmRelay` or `CudaIpcRelay`. Those relay mechanics are documented below because they are assigned owners and define non-default placements. The API/coordinator boundary still uses coordinator control messages; exact socket serialization and stage-runtime receive/send mechanics belong to the separately researched runtime boundary.

## End-to-end `/v1/audio/speech` call graph

1. `create_app` installs a `SpeechRequestValidator` and the speech route (`serve/openai_api.py:179-303`). `create_speech` generates `speech-<uuid4>` before parsing, parses JSON, and runs synchronous request/reference preparation in `asyncio.to_thread` (`1278-1303`). There is no public speech request-ID field; the generated ID is authoritative. Batch IDs are `speech-batch-<uuid4>` and item IDs append `-<index>` (`1364-1417`; `speech_service.py:447-468`).
2. `SpeechRequestValidator.parse_generation_request` performs raw type checks before Pydantic coercion, normalizes and validates the request, resolves reference media, then `build_generate_request` lowers it to a client `GenerateRequest` (`speech_service.py:193-230,394-427`). The request has one audio output modality, metadata `task="tts"`, and a `tts_params` dictionary. Its prompt is the text string when no reference exists, or `{"text": input, "references": descriptors}` when references exist (`890-898`).
3. `Client._build_omni_request` maps that request to `OmniRequest`: prompt becomes `inputs`; sampling, `stream`, stage overrides, and extra params become `params`; model and output modalities join metadata (`client/client.py:460-468,611-687`). The coordinator wraps it in `StagePayload(data={"raw_inputs": request.inputs})`, reserves the ID, records request state, and sends a `SubmitMessage` to preprocessing (`pipeline/coordinator.py:405-492`).
4. Default CosyVoice stage edges use `LocalStageDispatcher.send_payload` / `send_stream_chunk`, which await the registered receiver methods while passing the same Python payload/data/metadata references. The contract says receivers treat these as read-only unless projection produced an isolated object (`pipeline/local_dispatch.py:9-88`). Relay serialization, transfer buffers, control-plane `DataReadyMessage`, and `DataAckMessage` are bypassed for these local edges.
5. Terminal vocoder stream and completion messages enter the coordinator. For streaming requests, `Coordinator._handle_stream` puts `StreamMessage`s into a per-request unbounded `asyncio.Queue`; `_handle_completion` puts the successful terminal completion after earlier handled messages and removes active request state (`pipeline/coordinator.py:623-758`). `Client.generate` converts `StreamMessage` via `_default_stream_builder`; a terminal `CompleteMessage` arrives as its `.result` and is converted via `_default_result_builder` (`client/client.py:54-72,471-608`).
6. HTTP `stream=true` goes through `_speech_audio_response`; non-stream goes through `_await_speech_response` and `Client.speech` (`openai_api.py:1304-1361,1472-1620`; `client/client.py:211-276`).

## Speech ingress, references, IDs, and seeds

`CreateSpeechRequest` (`serve/protocol.py:325-370`) supplies `model`, required `input`, voice/speaker alias, response format, speed, stream flag, task/language/instructions, legacy `ref_audio`/`ref_text`, structured references, codec/duration controls, generation controls including seed, and per-stage params. Defaults are voice `default`, WAV, speed 1, and non-stream. Supported formats are WAV, MP3, FLAC, PCM, AAC, and Opus; public speed is constrained to 0.25–4.0 (`291-310`; `speech_service.py:242-277`). Streaming is accepted only with PCM; non-stream validates encoder availability before dispatch.

Fun-CosyVoice3 declares exactly one speech reference and forbids combining reference transcript with instructions (`models/fun_cosyvoice3/config.py:35-39`). Validation counts normalized reference descriptors, not source fields (`speech_service.py:317-350`). Structured references are normalized in listed order, followed by legacy `ref_audio`; an uploaded named voice is used only when neither explicit reference form is present and is forced to task type `Base` (`352-392,665-691`).

Reference representations are:

- A bare path is expanded and resolved to an absolute `audio_path` directly (`781-799`). This branch does not call the connector’s configured local-directory policy.
- `file://` requires an allowed local media directory, rejects a nonempty netloc except `localhost`, resolves the path, verifies it is inside that directory, is a file, and is at most 10 MiB (`preprocessing/resource_connector.py:286-300`; `speech_service.py:936-940`; `speech_limits.py:10`).
- HTTP(S) downloads synchronously in the preparation worker thread. With no domain allowlist, remote domains are allowed, while loopback/private/link-local/reserved/multicast/unspecified resolved addresses are rejected. Every redirect is rechecked, with at most five redirects; content length and accumulated body are capped at 10 MiB. Returned MIME must be `audio/*` or `application/octet-stream` if present (`resource_connector.py:199-267,302-334,398-458`; `speech_service.py:922-930`). Downloaded bytes are base64 encoded and labeled WAV unless the server supplied an audio MIME type.
- Data URLs must use base64, an audio MIME type, pass the estimated 10 MiB cap, and decode with base64 validation (`speech_service.py:1060-1094`). Structured `references.data` receives the same validation (`747-759,932-934`).
- Uploaded voices lower to an `audio_path`, stable normalized name and creation time, and possibly MIME/data plus transcript (`822-868,984-998`).

The request seed must be an integer (bool rejected) and nonnegative. When present it is copied both into `SamplingParams.seed` and `metadata.tts_params.seed`; absent means `None` is passed through sampling and omitted from `tts_params` (`speech_service.py:269-277,693-745,822-887`). Speech sampling defaults are temperature 0.8, top-p 0.8, top-k 30, repetition penalty 1.1; individually supplied fields overwrite them. `explicit_generation_params` records which of max tokens, temperature, top-p, top-k, repetition penalty, and seed were explicitly present, including explicitly supplied `null` after Pydantic parsing (`807-887`).

## Audio output semantics

`Client._set_audio_data` recognizes `audio_data`, then `audio`, then a serialized waveform byte buffer plus dtype/shape. The byte-buffer branch creates a NumPy view, reshapes it, and calls `.copy()`, severing ownership from the message buffer (`client/client.py:420-438`). Result building recognizes merged decode plus `code2wav`, `talker`, or `talker_stream`; otherwise it maps one result dictionary. Stream building preserves source stage identity and maps per-message fields (`471-608`).

Non-streaming `Client.speech` forcibly replaces the request with `stream=False`, gathers every non-null audio chunk, remembers the last advertised sample rate, and concatenates multiple arrays along the last axis for multidimensional data or axis 0 for 1-D data. Encoding runs in a worker thread. Usage and finish reason come only from the last generated chunk (`211-276`). The HTTP response body is encoded audio; MIME reflects the encoder result; `Content-Disposition` names the actual extension. Finish reason and prompt/completion/engine-time usage, when present, are exposed only in `X-Finish-Reason`, `X-Prompt-Tokens`, `X-Completion-Tokens`, and `X-Engine-Time` headers (`openai_api.py:1324-1361`).

`to_numpy` keeps NumPy as float32 without a copy when possible; detaches torch, moves it synchronously to CPU, casts float, converts to NumPy; turns sequences into float32; and interprets bytes as little-endian signed 16-bit PCM scaled by 1/32768 (`client/audio.py:110-135`). `encode_wav` clips to [-1,1], multiplies by 32767, converts to int16, interleaves channel-first 2-D input by transposition, and writes a PCM RIFF header (`162-203`). `encode_pcm` performs the same clip/scale/int16 conversion without a header and transposes 2-D input before `tobytes` (`288-294`).

Speed adjustment linearly interpolates to `max(round(samples / speed), 1)` samples and returns the original sample-rate number (`138-159`). Non-streaming applies this after gathering all audio. Streaming applies it independently to each emitted delta (`openai_api.py:1449-1469`). This changes duration/sample count, not the advertised rate.

For non-WAV compressed formats, stereo channel-first data is preserved when shape is exactly two channels; unsupported layouts and raw PCM are downmixed after shape normalization. WAV preserves channel-first multi-channel input. PyAV resamples to the nearest allowed codec rate when necessary, builds one planar float frame, flushes the encoder, and returns the container. MP3/AAC/Opus then try pydub if PyAV fails. The speech API sets `allow_format_fallback=False`, so unavailable/failing requested encoders become errors rather than WAV responses. FLAC uses soundfile (`audio.py:206-285,323-446`; `speech_service.py:801-804`).

Streaming raw PCM uses `select_audio_delta`: nonterminal chunks are treated as new audio and increment `emitted_samples` by their length; a terminal chunk is treated as aggregate output and only its suffix beyond all previously emitted samples is returned. Terminal length at or below the emitted count produces no bytes. Inputs are squeezed; remaining multi-channel arrays are mean-downmixed based on the smaller apparent channel axis (`audio.py:297-320`). The route consumes until it gets the first nonempty encoded delta, fixes its sample rate, then returns `audio/pcm` with headers `X-Sample-Rate`, `X-Channels: 1`, and `X-Bit-Depth: 16`. A later rate change raises. Raw streams carry no finish/usage headers or terminal frame (`openai_api.py:1472-1577`).

## Backpressure, cancellation, final ordering, and lifetime

Before HTTP response headers exist, `_speech_audio_response` races each `anext` against a 50 ms disconnect poller. A disconnect cancels the pending pull with a bounded 100 ms wait, calls coordinator abort, closes the async iterator, and raises cancellation. Once a first PCM chunk exists, the body generator yields it and then pulls/encodes one chunk per ASGI body iteration. If body iteration exits before normal exhaustion, its `finally` aborts and closes; on normal exhaustion it only closes (`openai_api.py:1472-1577,1623-1654`). `Client.generate` wraps the coordinator iterator with `aclosing`; `Coordinator.stream` aborts in its `finally` only if the request remains active, then removes queue/future ownership (`client/client.py:54-72`; `coordinator.py:363-403`). Abort work is held in a coordinator-owned task and shielded from caller cancellation; it broadcasts first, marks aborted, wakes stream consumers with a failed completion, and removes tracked state (`coordinator.py:520-601`).

Non-streaming races `Client.speech` against the same disconnect poller. Disconnect calls abort before cancelling the speech task; cancellation from any source also calls abort unless already done. Task cleanup is bounded, with late exceptions consumed by a callback (`openai_api.py:1580-1638`).

The API and client consume coordinator events sequentially. A terminal stream result carrying audio is not discarded: the raw speech loop encodes its audio before exhaustion. Coordinator stream queues are created with no `maxsize`, so HTTP/ASGI consumption does not impose bounded backpressure on terminal-stage publication. ASGI `yield` still naturally waits for each HTTP body send, but coordinator messages may accumulate independently (`coordinator.py:363-389,722-758`). No queue size, bytes queued, or HTTP write latency is recorded here.

For non-local relay sends, `CommEngine` creates a bounded queue per target (default 1024). `send_payload` and `send_stream_chunk` await `queue.put`, and then await a `ready` future resolved after relay write, pending-registration, and `DataReadyMessage` publication; they do not await receiver ACK. One worker serializes sends per target, preserving its queue order (`comm/engine.py:103-141,193-239,290-337,832-968`). Each published object is held in `_pending`. A watcher waits up to the default 30 seconds for `DataAckMessage`, marks all relay operations receiver-done, then awaits their completion; failure marks operations failed and awaits cleanup. The pending entry is removed afterward (`970-1088`).

`DataReadyMessage` permits exactly one of data (`data_ref`, optional nonnegative chunk ID), done signal, or error signal; done and error are mutually exclusive. `DataAckMessage` names the exact object ID and carries either success or a required error string (`proto/messages.py:17-158`). ACK generation after read and final stage signal ordering live in the separately researched stage-runtime owner. No claim about cross-socket ordering is made here.

## Data references and copy boundaries

`TransportKind`, `DataKind`, and `DataLayout` enumerate local object/CUDA IPC/SHM/Mooncake, payload/stream/metadata/KV/weight/MoE objects, and packed/raw/paged/bucketed/scatter layouts (`comm/data_ref.py:11-32`). `TensorMeta` records nested path, original shape/dtype/device, byte offset, and size. `BackendRef` carries transport-specific metadata and derives byte length from `transfer_info.size`. `DataRef` is a frozen version-1 control-plane pointer containing object identity, buffer reference, optional pickled header, tensor metadata, and metadata-tensor references; deserialization strictly checks primitive types and version (`35-212`).

`extract_tensors` recursively replaces all tensors in dict/list/tuple containers with path placeholders; `extract_cuda_tensors` replaces only CUDA tensors; `restore_tensors` reverses placeholders (`comm/stage_io.py:57-121`). Relay payload writes make every tensor contiguous, reinterpret it as bytes, copy it to the relay device when required, align each offset to its dtype element size, concatenate into one allocated byte tensor, and base64-pickle the tensor-free `StagePayload` header (`377-411,636-665`). With no tensors, a one-byte transfer is still allocated. Reads allocate a fresh byte destination on the relay device, wait for relay completion, form typed views by offset/shape, restore accelerator-origin tensors to the receiver-local accelerator when needed, reconstruct the payload, and call relay cleanup (`414-441,668-718`). Views retain the transfer buffer through tensor storage ownership.

Raw stream tensors follow the same contiguous-byte conversion and optional device copy. Metadata tensors are separate relay objects; non-tensor metadata remains inline in the `DataRef` (`444-567,596-633`). Small CPU stream tensors may instead be pickled inline when the tensor storage and final pickle are each at most 16 KiB and metadata contains no tensor (`272-334`). Direct torch CUDA IPC serialization uses `ForkingPickler` and carries CUDA storage-sharing objects in the control message. Payload direct IPC supports CUDA tensors only in payload data, not request tensors; stream direct IPC requires CUDA data, no CPU tensors anywhere, and at most 64 KiB of pickled non-tensor material (`141-265,337-374,793-835`). Process-local CUDA events are stripped from metadata before crossing a process boundary (`124-138`).

## Router and default/local transport

`CommRouter.__init__` records stage placement, same-process and remote targets, GPU identities, configs, lazy relay cache, peer-query cache, and transport trace state (`comm/router.py:29-64`). `outbound` selects `LOCAL_OBJECT` first, otherwise Mooncake for remote, intra-node platform transport for GPU-to-GPU, and SHM for other edges (`192-204`). Payload-aware routing chooses SHM for no/CPU tensors, intra-node transport for compatible CUDA payloads between GPU stages, and rejects mixed unsupported devices (`254-281`). Stream routing requires a tensor and selects Mooncake, SHM for a device-type mismatch, or intra-node transport for GPU stages (`206-223`). CUDA IPC peer failure falls back to SHM with one warning per reason (`66-150`). Relay instances are lazy and cached; defaults are two 512 MiB legacy credits, CUDA IPC 64 KiB slots, and SHM on CPU (`234-367`). Transport selection/change is observable through `comm_transport_selected` when comm tracing is enabled (`152-190`). `_tensor_devices` recursively classifies tensors while cycle-guarding containers (`375-399`).

On the reached default CosyVoice path, `LocalStageDispatcher.register/register_many` map names to live stage objects; `_get_stage` rejects missing targets; send methods await the receiver directly and pass references without serialization, copying, relay credits, transfer IDs, ACKs, or relay cleanup (`pipeline/local_dispatch.py:9-88`). Exact receiver queue behavior is a stage-runtime boundary.

## Relay owner mechanics (supported but not reached by default CosyVoice)

`relay/base.py` symbols: `register_relay` (17-32) installs/overwrites registry entries; `create_relay` (35-77) dynamically imports known backends and filters constructor kwargs; `RelayOperation` (80-100) defines metadata, completion, and optional receiver-success/failure hooks; `Relay` (103-136) defines put/get/cleanup/close; `CreditAllocator` (139-176) blocks on an asyncio credit queue and optionally maps credits to fixed offsets.

`relay/shm.py` symbols: `shm_create_from_tensor` (25-33) requires a CPU-convertible tensor, creates a new POSIX shared-memory block, and copies flattened NumPy bytes. `ShmOperation` (36-45) owns metadata/completed state. `ShmPutOperation` (48-98) closes the creator mapping immediately, holds a future until ACK, unlinks on timeout/failure, and always releases its semaphore credit once; receiver success/failure completes that future. `ShmGetOperation` (101-142) opens by name, creates a NumPy/torch view, checks destination capacity, performs a synchronous tensor copy, then closes and unlinks even on error. `ShmRelay` (146-207) limits outstanding puts with a semaphore, creates metadata with name/size/request ID, and leaves cleanup/close/reset as no-ops.

`relay/cuda_ipc.py` helper symbols: `_event_wait_threads_from_env` (37-44) reads a positive worker count; `_synchronize_cuda_event` / `_wait_for_cuda_event` (47-89) move event synchronization off the event loop and optionally finish an uncancellable launched GPU operation before propagating interruption; `_cuda_event_elapsed_ms` (92-101) is best-effort timing; `_parse_device_id` (104-107), `_ensure_peer_access` (110-129), storage handle dump/load (132-179), and slot math/layout records (182-203) implement CUDA identity/import and sizing.

`_ReceiverAckOperation` (206-244) holds arbitrary source references until ACK completion. `CudaIpcPutOperation` (247-322) additionally holds source tensor/events and allocated slots; ACK releases slots, while timeout/failure marks the entire relay failed and does not return slots. It emits sender ACK/copy timing. `CudaIpcGetOperation` (325-419) waits for the receiver copy event in the thread pool, holds imported pool and related references until completion, and can shield uncancellable work through cancellation/timeout. `_ContiguousSlotAllocator` (422-538) reserves contiguous runs under an asyncio lock/event, blocks until a run exists, validates exact aligned releases, and exposes fragmentation counters to tracing.

`CudaIpcRelay` (542-1209) lazily allocates one GPU uint8 pool. Legacy pool sizing is `slot_size_mb * credits`; current allocation uses fixed 64 KiB-default slots. One storage export is cached per receiver identity because each export has one consumer refcounter token. `put_async` requires CUDA input and receiver ID, copies contiguous source bytes nonblocking into reserved slots on the current stream, records an interprocess ready event, exports pool/event metadata, and returns an ACK-held put operation (`730-845`). `get_async` imports/caches the remote pool, validates peer access and every range/alignment field, makes a fresh destination copy wait on the sender ready event, records a completion event, and returns a get operation (`847-964`). Generic request cleanup is a no-op; `close` clears imported/exported references and shuts down wait workers without waiting (`1197-1209`). KV registration/export/copy symbols (`966-1195`) validate compatible pools, cache per-destination exports, wait on a source-ready event, invoke the per-layer transfer kernel for selected pages, and hold indices/imports until the recorded event completes; they are unrelated to the CosyVoice audio path.
